## 1. 调研方法和证据边界

- 本轮直接读取下列公开原始页面的 HTTP 200 HTML，提取页面正文核对；不依赖搜索结果摘要。没有安装或运行动作，没有访问 Quicker 个人配置、私有常用语或真实个人资料。
- Quicker 两条来源是作者发布在 Quicker 动作库的公开动作说明，能确认“该动作页面如何描述功能”，不等同于 Quicker 全部动作或所有目标软件的实际运行验收。

- 本库能力由当前生产源码确认。这里的“已有实现”不等同于所有平台都完成真实宿主验收；本次调研未重新启动或附着思源/Electron，B-001–B-005 继续按 [BLOCKERS.md](../BLOCKERS.md) 解读。

**本轮补充确认：多块条目完整性未完成。** 对历史已记录的“段落/列表拆成兄弟块”返回形状，真实 `LibraryService` 离线复现显示：创建回执成功，但只给首块条目属性，随后预览数据链、实际执行器复制、JSON/Markdown 导出均只取得首块；删除条目仍留下无属性尾块。没有连接真实宿主，详细证据、局限和保守止损建议见 [多块完整性记录](multiblock-integrity-2026-10-18.md)。下表中的类型分派是已有代码语义，不能覆盖该创建边界缺陷；下文所有复杂模板均为待验证方案，不建议在缺陷修复前新增导入。

### 4.1 可直接复制的文本/Markdown/代码正文

**邮箱地址（`text`）**，别名“演示邮箱，替换后再用于实际沟通”，正文：

```text
demo@example.com
```

**收件地址（`text`）**，提供一个立即可看到效果的无效示例；另一条已有 ask 模板用于实际填写演示：

```text
收件人：示例用户（请替换）
地址：示例省 示例市 示例区 示例路 00 号
电话：<请填写手机号>
邮编：<请填写邮编>
```

**身份信息填写（`text`）**，示例本身保留明确标注，不生成可通过校验的证件号：

```text
姓名：示例用户
证件号码：000000000000000000（不可用示例，请替换）
用途：演示常用资料条目的保存与调用
```

如果用户将其改成真实常驻资料，正文会成为思源真实块，按用户的思源工作区同步/备份设置处理；本插件不是密码或证件保险箱，也不提供身份证识别、有效性核验或额外加密能力。示例中的提示只承担说明，不伪装成已经实现的安全功能。


```markdown
- [ ] 确认入职日期
```

### 4.2 图片、PPT、简历文件和引用的说明正文

当前可先把以下四项做成 **`markdown` 使用说明条目**；标题明确以“如何添加…”开头，不伪装成已就绪的 `image`/`asset`/`blockref`。用户真正完成前置操作后才创建相应真实类型。

**如何添加证件资料图片（示例说明）**：

```text
1. 在思源文档添加一张自己的示意图片；演示图请使用无真人、无证件号、标有“示意 · 非证件”的普通资料卡。
2. 右键该图片，保存为常用条目；给它设置“图片”“资料”等标签。
3. 在小驴常用中搜索该标题。当前预览会显示 Markdown 路径；可打开原图，或插入到思源文档。
4. “复制”得到 Markdown 链接，不会把图片位图写入系统剪贴板。
```

**如何添加公司介绍 PPT（示例说明）**：

```text
1. 先把真实的公司介绍.pptx 作为附件添加到思源文档。
2. 右键附件链接，保存为常用条目；类型为“附件”，分类可设为“商务”。
3. 搜索后可插入附件链接、复制 Markdown 链接或打开资源。
4. 小驴常用当前不在预览区播放 PPT，也不会直接向聊天软件发送文件。
```

**如何添加简历文件（示例说明）**：

```text
1. 简历正文适合保存为 Markdown，便于逐段编辑和引用。
2. 要保留排版的 PDF/DOCX 版本，先作为附件添加到思源，再捕获附件链接。
3. 给文件标题加版本或日期，例如“简历-产品岗位-2026-10”；搜索时用“求职”“简历”等标签筛选。
4. 复制附件得到链接；发送实际文件须从思源或系统文件操作完成。
```

**如何建立公司简介引用（示例说明）**：

```text
1. 先导入或自己编写“公司简介正文”条目，并打开它在思源中的来源。
2. 对该真实块使用“保存块引用”，或在标签视图中加入引用入口。
3. 在搜索面板可选择插入引用、嵌入或原文；修改来源后再次调用会读取当前正文。
4. 不要把别的工作区块 ID 或教程里的假 ID 填为目标。
```

## 5. 推荐的内置方式与状态标注

### 近期：先标明缺陷，完整性收口后沿用显式导入

1. 把入口名称从偏 AI 的“提示词场景包”逐步改成涵盖全部场景的“常用内容示例”，保留包 ID 兼容；旧模板不要因改名重新生成逻辑 ID。
2. 邮箱、地址、客服等已有模板保留并标注多块限制；身份信息无效占位、公司/简历正文、URL、代码/结构例子和四条媒体/引用使用说明按上表评审。**缺陷收口前不扩充复杂导入，也不把文字说明伪装成八类真实资源已就绪。**
3. 每条提供“用途、输出、前置条件”。描述尽量放别名/入口说明，避免操作说明混入对外输出；当前 alias 还承担检索别名，长篇说明应放独立“如何添加…”条目。
4. 复用现有“设置→导入内置分类模板→重复处理策略”管道。默认推荐“跳过重复”；不启动时自动写库，不默认覆盖用户编辑过的示例。分组勾选导入、首跑勾选和独立示例预览页都是后续设计，当前不能宣称已有。
5. 模板数量以实际解析结果为准。当前曾发现提示文案仍写 16、包实际 20 的漂移；不要在多个文案中重复写死数量。

### 后续可选：安装真实资源与生成引用的完整示例包

只有确实需要“一次导入就能点开真实示意图/PPT/PDF”时，才增加有明确范围的资源安装能力。该能力**尚未开发**，需要单独任务/ADR，而不是向字符串模板塞不存在的 `assets/` 路径。

- 资源采用原创、无个人数据的小文件，附来源/许可、大小和哈希；示意图片使用普通资料卡设计及明显水印，不制作真实证件外观或可认证材料。
- 用户先看到条目/资源清单并确认；通过经核实的官方资源 API 写入思源，读取实际返回路径，再创建条目。资源写入失败时不创建“已就绪”的附件条目。
- 公司简介引用要在真实正文条目创建后读取实际块 ID，再创建引用入口；重复安装要识别既有逻辑条目，不能写死跨工作区块 ID。
- 失败、重试、部分成功和用户编辑保护需要明确回执；清理只处理可证明由本次创建且未变化的对象，不盲删来源或用户资源。
- 图片缩略图、PPT 内嵌预览、位图复制、系统文件复制、跨应用发送是各自独立功能；资源包不自动使这些能力成立。

### 界面上的诚实标注

| 情况 | 应显示的状态/动作 | 不能出现的误导 |
| --- | --- | --- |
| 无真实图片/附件 | “示例说明 · 请先在思源添加资源”；入口为“查看添加方法” | 有可点击的“打开 PPT/复制图片”却只指向假路径 |
| 已有真实图片/附件 | “预览为资源路径”；“复制链接”“插入图片/附件链接”“打开资源” | 暗示复制位图、复制文件或已提供 Office 阅读器 |
| 块引用未绑定真实目标 | “请先选择来源块”；禁用插入引用/嵌入并给原因 | 把合法格式的虚构块 ID 当作可调用目标 |
| 资源或来源失效 | 保留失效状态；提供可行的重试/恢复来源/编辑入口；复制链接有清楚回执 | 静默隐藏条目或显示成功打开 |
| 无活动编辑器或移动端插入待验 | 沿用既有复制降级和待验证提示 | 把复制成功写成实际插入成功 |
| AI 与个人资料示例 | AI 默认关闭；真实 AI 链路尚未验证；正文出域继续受既有双开关约束 | 为示例自动开启 AI 或把身份证/简历默认为发送给模型 |

## 6. 方案实施后的验收条件

- 用户从空库/帮助/设置能找到示例入口，导入前知道会新增哪些类型；取消没有新增块。
- 可直接导入的每一条都有有效逻辑 ID、正确类型/分类/标签；重复导入默认跳过，不覆盖修改；计数来自实际包而非过时文案。
- 例子至少说明全部八种 `ItemType`，其中媒体/引用明确区分“真实条目可用”和“当前仅说明、依赖用户先添加”的状态。
- 对 text/markdown/url/code/structure 核对实际复制载荷、插入后内核读回和正文完整性；尤其验证多块内容没有仅存第一块。新增/修改门禁时遵循本仓要求做违规注入和恢复正向复验。
- 对带资源包（若立项）核验图片、PPT/PDF 实际字节与返回路径，确认资源存在并可打开；不能仅用解析器通过或假路径测试验收。
- 当前纯文本预览、图片位图复制、系统文件复制、Office 内嵌预览、Android/真实 AI 和宿主连续嵌入边界，都按真实实现与验收层级标注，不因示例包导入成功而移除。

本次建议的产品价值是让用户看见“邮箱/地址是可复用资料，简历/公司介绍可分正文和附件，图片依赖思源资源，块引用保留来源更新”。近期先提供清楚的能力和添加说明；多块完整性收口后再扩充可导入模板，完整二进制示例安装作为可选后续工作。
