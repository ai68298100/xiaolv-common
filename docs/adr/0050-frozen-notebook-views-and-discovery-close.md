# ADR 0050：笔记本视图固定目标与发现窗口关闭确认

## 状态

已采纳，T-0080 / R227 实现与验收完成（2026-10-16）。

## 问题

此前笔记本视图只存入口文档 ID，重开时从该文档推断笔记本；入口文档跨笔记本移动后，视图会扫描新笔记本并自动选中候选，偏离用户保存的范围。保存视图的笔记本 ID 校验还误用纯数字正则，无法保留思源真实的块 ID 形态。

发现窗口同步后用原生 `window.confirm` 确认关闭，Electron 隐藏实例无法完成其现场验收。替换为宿主 Dialog，同时保留取消后的撤销入口，防止确认绕过正在写入的保护。

## 决策

- 服务会话以 `sourceNotebookId` 暴露本次实际扫描的单个笔记本 ID。保存取会话快照，不能在命名时再次从可能已移动的入口文档推断范围。
- 新笔记本视图保存 `targetNotebookId`，将 `targetDocId` 归一化为空；重开传 `initialNotebookId`，只调用 `discoverNotebook`。目标不可用或能力缺失时明确失败，不回退到当前文档或其笔记本。
- 旧记录没有固定笔记本 ID 时保留展示，但禁止重开并提示从原笔记本重新保存；不猜测迁移目标。同笔记本、同名、同标签规则跨入口文档保存保持幂等。
- 有可撤销批次时 `close()` 同步返回 `false` 并打开一个官方确认 Dialog。取消/Esc 不关闭会话，恢复关闭按钮焦点；明确关闭保留已加入条目，只结束本窗口撤销入口。
- 明确确认仍走正常关闭路径，重新检查 UI 写入状态和服务 `closeSession` 回执。`close(true)` 仅用于插件卸载清理，用户确认不调用强制路径。
- 取消在关闭动画之前终止提交；父窗口销毁清理子窗，重复/迟到提交无效。输入焦点默认落在取消按钮。
- 从另一保存视图或发现入口切换时，将后续打开动作交给关闭成功回调。明确关闭后继续原请求，取消不执行；重复关闭请求沿用第一个确认，不替换其目标；卸载清理丢弃待执行请求。

## 验证边界

单测、生产 DOM 交互与真实 Electron 分别记录；新增门禁必须执行违规注入、恢复和正向复验。Android、真实 AI 与宿主连续动作选区边界不因本次修复改变。现场证据由当期账本与 Electron 验收记录跟踪。

已通过 445/445 单测、71/71 生产 DOM 交互、UI smoke、隔离内核核心 12/12 与发现链路；服务/装配/交互/几何门禁的真实违规注入均失败，恢复后复验通过。固定思源 3.8.7 / Electron 44.7.0 现场 21/21，覆盖入口文档真实跨笔记本移动、保存规则重载、批次关闭取消/确认和成功关闭后续开新入口；不把内部方法调用次数当成现场已测指标。详见 [Electron 验收记录](../electron-acceptance-2026-10-16.md)。
