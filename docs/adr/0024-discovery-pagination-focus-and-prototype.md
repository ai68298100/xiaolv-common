# ADR 0024：发现页分页焦点与原型镜像

- 状态：接受
- 日期：2026-10-13
- 关联：T-0048 / R195 / ADR 0019

## 背景

发现页每页最多展示 100 条候选。翻页时 `renderList()` 清空并重建整个列表，聚焦中的分页按钮会随旧节点移除，键盘用户的焦点因此回到文档主体。现有 smoke 只使用两条候选，没有触发分页。生产发现页还包含范围选择、扫描目标、过滤、预览和批量收录等完整交互，但原型只有通用状态矩阵，缺少页面视觉镜像。

## 决策

1. 分页控件使用稳定语义 ID；页码更新与列表重绘后，焦点恢复到对应方向的分页按钮。若目标动作因边界而禁用，则聚焦另一个可用分页按钮；只有没有可用分页动作时，才将焦点置于结果列表容器。
2. UI smoke 以 101 条以上候选触发真实分页监听，检查页码、首尾候选和 `document.activeElement`，覆盖下一页、上一页和连续翻页。
3. 原型新增发现页桌面双栏以及窄屏纵向布局，呈现生产页面现有范围/目标、筛选、候选、预览、分页、批量收录、失败/空结果与状态回执。双主题引用同一视觉语义；窄屏不改称移动 sheet，因为生产发现页使用根容器滚动。
4. 本批只为分页与焦点恢复添加稳定 ID 和行为证据；发现页其他控件仍按 ADR 0019 逐批映射，不以页面原型替代其行为验收。

## 取舍

- 保留列表整体重绘，避免为了焦点保留而引入多余 DOM 状态；只恢复用户原来操作的分页方向。
- 新增候选数据只用于 harness 大列表场景，不改变生产数据来源或分页上限。
- 原型是静态视觉规范，生产 smoke 才证明分页行为；Android/Electron 宿主差异仍需现场验证。

## 验证

- `test:ui` 生成超过 100 个候选，连续键盘翻页验证活动元素、页码播报语义、首尾候选和边界按钮；普通两条候选场景只检查结果列表语义，不要求分页器存在。
- 移除焦点恢复逻辑的负向注入需令对应断言失败，恢复后重跑。
- 渲染桌面/窄屏/移动原型屏并核对生产发现截图；重跑 `check`、`test`、`build`、`test:ui`、`test:ix`、扫描/包检查和差异检查。

## 未决

- 发现页除分页器外其余控件仍未全量映射到稳定 ID；继续按页面扩展。
- 真实思源 Electron 和 Android 触控验收仍按 B-001/B-002/B-003。
