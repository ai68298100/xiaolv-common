# ADR 0056：全表面审计、侧车保护与完整导出

日期：2026-10-18 ｜ 状态：已采纳 ｜ 任务：T-0086–T-0088 / R233–R235

## 背景

用户要求重新检查现状、UI 与原型一致性、功能是否可用、代码错误及 GitHub 待办，并调研 Quicker 等工具的多类型内置示例。基线为 main `dc778017f5dd3557d31a749f534ca2f9c084712e`，发布版本 v0.4.2。

## 决策

1. 审计分清本轮源码/离线 Chrome 证据、既有内核/特定 Electron renderer 观测与未验证设备/服务能力。B-005 继续开放，本轮不启动或附着思源宿主。
2. 已确认的不完整导出不得下载为成功备份：索引不完整、任一正文读取失败、超出包总长度边界时，终止并给出错误。无条目丢失的成功回执才可称完整导出。
3. 无法可靠读取或识别的侧车状态禁止写回。特别是未来版本状态不能被当前版本默认值覆盖；可读的兼容状态继续按既有迁移规则使用。
4. 保留代码片段字面内容契约。内置 SQL 示例改为可直接复制的普通表名，不能用不会展开的 ask 变量暗示代码模板可填写。
5. 修正模板数量、移动端“选择后执行”说明及图片/附件能力说明，并同步原型/夹具。媒体仅有 Markdown 原文预览与链接文本复制；查看资源走宿主打开来源，不能宣称文件发送或内置 PPT 阅读器。
6. 多类型示例本轮交付官方来源调研和具体样例/实现方案。沿用显式、可预览、可取消的可选导入；图片/附件必须先有真实资源，块引用必须先有真实块。不会把虚构 assets 路径或块 ID 混入可用模板包。邮箱、地址等已有模板与新增待开发的媒体示例分别标注。
7. GitHub 只读核验 issue/PR/CI/release/附件与安全功能状态；未获消息发送指令，不发评论、提单或上游报告。仓库既有推送授权不等于本轮需要发布；版本保持 0.4.2，修改归为本地待发布。
8. 本轮发现多段 Markdown 仅登记首块的既有缺陷，记 B-006 / T-0089。它涉及真实块树与旧数据归属，不能在 B-005 下以新包装字符串和受控假内核通过冒充修复。先在捕获/导入说明/帮助和状态矩阵明确边界，暂停把多段示例称为现场完整可用；后续采用 [ADR 0057](0057-multiblock-anchor-parts.md) 的新写条目 `custom-xlc-parts` 止损方案，并等待安全内核验收。已存在的相邻块不自动合并或删除。

## 验证

本轮新增/修改契约测试必须使用实际源码违规注入，确认失败后恢复复验。既有 Chrome UI/交互检查使用本机 Chrome，生成基线文件须保留或恢复其原字节。最终结果记录在当期账本与 2026-10-18 审计报告。
