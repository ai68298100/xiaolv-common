# ADR 0053：协议插入入口的目标生命周期

## 状态

已接受，T-0083 / R230（2026-10-16）。

环境补注（T-0084）：镜像额外启动日常工作区内核，整体隔离失效；目标竞态的临时 renderer 局部读回保留，不能作为日常环境未触碰的证明。详见 [事故记录](../electron-isolation-incident-2026-10-16.md) 与 ADR 0054。

## 问题

T-0081 在执行器读取正文前冻结目标，但协议 `service.insert` 更早的 `get(itemId)` 和幂等锁等待仍在冻结之前。真实服务与执行器的延迟查询复现得到 `lookup:A → capture:B → insert:B → release:B`：调用始于 A，查询期间切换到 B，结果却向 B 插入。此前同窗 UI 验收和执行器单测没有覆盖该入口。

## 决策

- 在协议插入调用第一次异步等待之前建立目标作用域，包括查询和锁等待；目标失效只复制，不改投后来激活的编辑器。
- 目标作用域由执行器管理：同步捕获，等待整个回调完成后 `finally` 释放一次。传给执行器的显式目标由外层作用域管理，执行器不得重新捕获或提前释放。
- 查询失败、异常、成功回执缓存命中与重复幂等调用都必须释放本次拥有的句柄；幂等键、串行执行和成功回执复用语义保持。
- `copy`、`copy-content` 和 `open` 不申请插入句柄。兼容既有不提供目标作用域方法的测试执行器桩，生产执行器始终提供此能力。

## 验证边界

使用真实源码服务与执行器、可控延迟和具有释放后失效语义的宿主桩，核对目标身份、写入次数、回执和释放顺序；注入旧入口行为确认新门禁失败，再原字节恢复复验。该层验证不冒充真实 Electron 在查询期间切页的端到端现场；宿主副本后续复验另行记录。

## 最终结果

真实源码专项 11/11、全套单元 468/468，七项违规注入分别检出并恢复。思源 3.8.7 / Electron 44.7.0 隔离副本仅延迟一次真实 `getBlockAttrs` 请求、不修改响应，查询期间真实切换到 B；旧构建两个场景均新增错误引用到 B，快照门禁准确失败。新构建 4/4：原目标 A 仍连接时只向 A 新增精确引用；A 已关闭时精确复制，A/B 块 ID、正文与属性快照均不变。具体部署身份、延迟请求和回执见 [现场记录](../electron-acceptance-2026-10-16.md)。这项实证补齐协议查询阶段，不解除宿主嵌入后选区、Android 或真实 AI 的既有边界。
