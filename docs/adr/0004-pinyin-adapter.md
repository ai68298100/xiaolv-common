# ADR 0004：拼音 = 可替换适配层，默认实现不引入拼音库

日期：2026-10-06 ｜ 状态：已采纳

## 背景

需求三.4：搜索需支持拼音首字母/模糊匹配；若拼音库不适合引入，先抽象可替换的拼音适配层并保持基础中文搜索完整可用。雷切 R2 已验证 vendor tiny-pinyin（MIT，gzip ~3.5KB）可行。

## 决策

- `src/model/pinyin.ts` 定义 `PinyinAdapter` 接口：`expand(query: string): string[]`——把用户查询词展开为「等价匹配串集合」（默认：原词单项）。
- 默认实现 `createNoopPinyinAdapter()`：恒返回 `[query]`，零开销、零依赖。
- 搜索管线（`src/model/search.ts`）只依赖接口；未来接入 tiny-pinyin 只需提供 `createTinyPinyinAdapter()` 并在装配处替换一行，不改搜索逻辑与测试语义（新增适配器需带独立测试）。

## 理由

- 首版先守住「基础中文搜索完整可用」这条硬线；拼音库引入是体积与多音字正确性的双重权衡，应在真机验证基础链路后再做（B-001 之后）。
- 适配层让「是否引入、引入哪个库」保持为可逆决策。

## 后果

- 首版不支持 `cw`→「常用」这类首字母命中（产品内能力声明如实标注）。
- 适配层接口保持极窄（一个方法），避免为未来假设过度设计（需求六.8）。
