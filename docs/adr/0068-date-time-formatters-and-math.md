# ADR 0068：自定义日期时间格式化与算术组合引擎 (G16) 契约

## 状态

已接受，T-0127 / R274（2026-10-20，对标 Espanso / TextExpander / Quicker 日期时间进阶能力，落地 G16）。

## 背景与上下文

在 R160 与 T-0112 中，小驴常用先后引入了相对日期算术（`{{xlc:date|+3d}}`）与中文自然语言偏移（`{{xlc:date|明天}}`）。但在深度办公与文本扩展场景中，用户仍面临明显的格式化限制：
1. **硬编码格式限制**：`{{xlc:date}}` 固定输出 `YYYY-MM-DD`，`{{xlc:time}}` 固定输出 `HH:mm`，无法自定义如 `YYYY年MM月DD日`、`YYYY/MM/DD`、`HH:mm:ss`、`YYYYMMDD` 或 `YYYY-MM-DD dddd`；
2. **算术与格式无法结合**：当用户需要计算“截止日期”并在合同或通知中显示为中文格式（如 `2026年10月23日`）时，现有逻辑仅能输出 `2026-10-23`；
3. **时间与周几不可定制**：`{{xlc:time}}` 与 `{{xlc:datetime}}` 不接受任何参数，带参直接被拒绝；`{{xlc:weekday}}` 仅能输出「周X」，无法切换为「星期X」或英文星期名。

## 决策

1. **轻量纯函数格式化引擎 (`formatDateTime`)**：
   - 在 `src/model/placeholders.ts` 实现零依赖的模式替换引擎；
   - 支持主流时间令牌：
     - 年：`YYYY`（4位完整年份）、`YY`（2位紧凑年份）；
     - 月：`MM`（2位补零 01-12）、`M`（1-2位 1-12）；
     - 日：`DD`（2位补零 01-31）、`D`（1-2位 1-31）；
     - 时：`HH`（24小时制补零 00-23）、`H`（24小时制 0-23）、`hh`（12小时制补零 01-12）、`h`（12小时制 1-12）；
     - 分：`mm`（2位补零 00-59）、`m`（0-59）；
     - 秒：`ss`（2位补零 00-59）、`s`（0-59）；
     - 星期：`dddd`（中文长形式：星期一..星期日）、`ddd`（中文短形式：周一..周日）；
     - 时段：`A`（中文上午/下午）、`a`（英文 am/pm）。

2. **复合语法解析策略 (`resolvePlaceholder`)**：
   - 保持带参语法严格使用 `|` 分隔符，严禁引入 `:` 防止 Lute 转换 emoji 短代码；
   - `{{xlc:date|...}}`：
     - 若参数为相对偏移（如 `+3d`、`明天`），且无后续格式段，输出默认 `YYYY-MM-DD`；
     - 若参数为自定义格式（如 `YYYY年MM月DD日`、`YYYY/MM/DD`、`YYYYMMDD`），直接格式化当前日期；
     - 若参数为复合形态（`MATH|FORMAT`，如 `+3d|YYYY年MM月DD日`、`明天|YYYY/MM/DD`），先执行日期偏移运算，再将运算结果经目标格式渲染。
   - `{{xlc:time|...}}`：
     - 支持自定义格式（如 `HH:mm:ss`、`HH时mm分ss秒`、`hh:mm A`）；
     - 支持时间相对偏移（如 `+1h`、`-30m`）及复合格式（`+2h|HH:mm:ss`）。
   - `{{xlc:datetime|...}}`：
     - 支持自定义格式（如 `YYYY-MM-DD HH:mm:ss`、`YYYY/MM/DD HH:mm`）；
     - 支持相对日期偏移后格式化（如 `+1d|YYYY-MM-DD HH:mm:ss`、`明天|YYYY/MM/DD HH:mm`）。
   - `{{xlc:weekday|...}}`：
     - 缺省输出短格式「周一」；
     - 支持参数 `full` 或 `dddd` 输出「星期一」；
     - 支持参数 `en` 输出英文「Monday」，`en_short` 输出英文缩写「Mon」。

3. **安全边界与向下兼容**：
   - 100% 保持既有单测与历史占位符行为完全不变；
   - 未知 token 或非法模式返回 `null`，保持原始 `{{xlc:...}}` 占位符原文不被吞噬；
   - 纯函数模型，不触碰任何数据库、网络或宿主状态。

## 结果与证据

- 单元测试增至 610+ 项，覆盖纯日期格式、纯时间格式、完整日期时间、星期定制、算术与格式复合叠加；
- 严格负向验证：故意阻断格式化分支或返回空值，测试精准检出失败；恢复后复验全绿；
- 全套工程门禁（`check:errors`、`check`、`build`、`test:ui`、`test:ix`、`scan`、`check:package`）全数通过。
