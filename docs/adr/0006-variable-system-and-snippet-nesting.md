# ADR 0006：变量系统与片段嵌套 = 插入时展开 + 可见兜底 + 深度受限

日期：2026-10-07 ｜ 状态：已采纳 ｜ 落地：R67（F1/F2）、R72（F5）

## 背景

同类产品调研（TextExpander fill-ins、Espanso forms、Templater cursor、片段嵌套）表明：变量与插入时表单填充是片段工具的合格线能力。插件已有 5 个静态占位符（R6/R11），需要扩展为完整变量系统，且新增条目间引用（片段嵌套）。

硬约束（ADR 0002/0003、需求边界）：存储内容永远保留模板原文（真源安全）；code 条目中的 `{{xlc:…}}` 是字面文本（R23）；不使用 SQL；外部文本按纯文本渲染。

## 决策

1. **双语法族分离**：`{{xlc:ask:…}}`（填充变量）与 `{{xlc:date}}` 等动态占位符分属两个模型与两条替换路径——ask 在插入前由填充卡片收集（值仅作用于本次、不回写库），动态占位符在插入/复制时由执行层替换。共享 `xlc:` 命名空间避免与思源模板冲突。
2. **兜底可见不静默**：插入路径上未填充的 ask 展开为 `__名称__`（思源模板占位惯例，可见可改）；复制路径保持模板原样（复制是给编辑用的）。光标标记 `{{xlc:cursor}}` 在插入时移除（官方 API 无法定位文内光标，光标自然落于内容之后）——诚实降级并记录于文档。
3. **code 条目一律字面**：变量/ask/片段在 code 条目中不做任何处理（沿用 R23）。
4. **片段嵌套**：`{{xlc:snippet:标题}}` 在插入与预览前展开（预览所见 = 插入所得，三处统一：预览接口/填充卡收集/执行器）。maxDepth 默认 3（引用层数）；环检测按路径增删 seen（兄弟/菱形引用允许）；标题缺失/成环/超深 → `__片段：标题__` 可见标记。
5. **元数据快照**：ask 数量在写入期落 `custom-xlc-vars` 块属性（列表徽标零内核调用）；行为始终以插入时现场内容为准，徽标仅为提示。
6. **使用计数**：插入/复制成功 +1，存侧车（非真源、可重建可清空、可关）；「常用」排序 = 次数 × 最近使用。

## 后果

- 正面：变量与嵌套能力对齐同类合格线（TextExpander/Espanso/Templater），且独有「真源 + 填充」组合；徽标/提示行零额外内核调用。
- 代价：旧条目无 vars 属性则无徽标（行为不受影响，诚实降级）；填充卡是插入路径上的一步交互（设置可关）。
- 拒绝的替代方案：全局热字符串自动替换（宿主输入拦截风险高、越界）；展开结果回写库（破坏真源不可变）。
