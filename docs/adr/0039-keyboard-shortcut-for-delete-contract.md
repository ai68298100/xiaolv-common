# ADR 0039：列表条目快捷删除与二次确认契约

## 状态

已采纳（2026-10-14，T-0066 / R213）。

## 背景

在经历前续多轮迭代后，常用语的调用（`Enter`、`Ctrl+Enter`、`Alt+1~9`、`Alt+Shift+1~9`）、新建（拖拽放置、`Ctrl+V`）、编辑（`Ctrl+E`）和克隆（`Ctrl+D`）已全面实现全键盘覆盖。
然而在条目清理与维护场景中，删除操作此前仍只能通过鼠标右键动作菜单或点击详情区按钮，缺少快捷键支持，导致全键盘工作流在删除环节受阻。同时，删除属于破坏性操作，必须严格防范在搜索输入框输入文本时的按键冲突与误删。

## 决策

1. **分级快捷删除按键策略**：
   - **显式意图快捷键**：支持 `Alt + Delete`（macOS 下 `⌥ + Delete` 或 `⌥ + Backspace`），不论焦点在搜索框还是列表区均可触发；
   - **列表焦点快捷键**：仅当焦点处于非编辑控件（`!active?.matches("input, textarea")`）时，允许按下独立 `Delete` 键触发；
2. **输入框防误触绝对红线**：
   - 当焦点处于搜索输入框（`.xlc-search-input`）时，单独按下 `Delete` 或 `Backspace` 严格作为原生文本编辑处理，**绝对严禁**拦截为条目删除；
3. **强制二次确认与数据真源保护**：
   - 快捷键触发后**绝不静默删除**，一律唤起标准二次确认弹窗（`confirmDelete`），向用户明确说明仅从常用库解除标记、思源笔记中的原始块依然保留；
   - 只有用户在确认弹窗中显式点击确认后，才执行 `removeItem`，并同步清理索引缓存、收藏列表、最近记录与使用统计，随后自动从列表中移除；若取消则无任何副作用；
   - 处于第三方虚拟 Provider 分区时严格禁止触发本地删除；
   - 增加 `if (e.repeat) return;` 杜绝长按连发。

## 验证与边界

- 单元测试覆盖快捷删除按键判定逻辑、搜索框内按键隔离、虚拟条目排除与防长按保护；
- 生产 UI 交互审计验证 `Alt+Delete` 与列表区 `Delete` 能够准确捕获条目 ID 并唤起确认对话框；
- 移动端维持长按弹出动作菜单的触摸交互。
