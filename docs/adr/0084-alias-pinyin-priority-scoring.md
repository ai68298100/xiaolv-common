# ADR 0084：别名拼音与缩写专属高权重检索排序加固 (G32) 契约

## 状态

已接受，T-0144 / R291（2026-10-20，对标 Alfred Keyword Prefix / Raycast Alias Boost，落地 G32）。

## 背景与上下文

小驴常用已具备基于标题、别名、正文摘要与标签的综合打分机制，并在 R286 引入了唯一别名精确匹配（`findExactAliasMatch`）。但是在检索场景中：
1. **缩写与前缀痛点**：当用户只输入了别名的前缀（例如别名为 `delay_reply`，用户输入 `del` 或 `delay`），或者输入了中文别名的拼音缩写（例如别名「退款」的拼音首字母 `tk`）时，若正文中包含大量重复的高频词，可能导致正文命中的长条目打分意外超过了用户显式设置了别名的模板；
2. **行业对标**：在 Raycast 与 Alfred 中，“别名（Alias / Keyword）”是用户最强烈的检索意图表达，别名前缀与别名拼音命中的优先级天然应压倒普通正文摘要命中。

## 决策

1. **别名专属打分加权 (`src/model/search.ts`)**：
   - 在 `matchEntry` 中扩展对 `entry.alias` 的多维度加权体系：
     - **别名完全吻合**：原得分 + 400（最高优先级，确立绝对首位）；
     - **别名前缀吻合**：原得分 + 200；
     - **别名拼音完全吻合**：原得分 + 150；
     - **别名拼音前缀吻合**：原得分 + 100；
2. **纯函数与零开销**：
   - 依赖现有 `SearchContext` 中的拼音适配器，不额外增加磁盘或网络开销；
   - 保持排序平稳收敛。

## 结果与证据

- 单元测试验证别名命中打分压倒普通长正文，别名拼音首字母优先命中；
- 负向验证与全门禁通过。
