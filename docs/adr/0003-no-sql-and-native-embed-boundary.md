# ADR 0003：禁用 SQL 查询 API；嵌入块使用宿主原生语法的边界

日期：2026-10-06 ｜ 状态：已采纳

## 背景

需求四.10：禁止使用任意 SQL、任意网络服务或私有 DOM 作为核心依赖。但思源的「嵌入块」唯一原生语法形如 `{{select * from blocks where id='...'}}`（SQL 形态）。

## 决策

1. **插件自身绝不调用 `/api/query/sql`**，也不自拼任何 SQL 发给内核。索引遍历用 `/api/block/getChildBlocks`（文档序）、失效检测用 `/api/block/checkBlocksExist`、内容用 `getBlockKramdown`、属性用 `getBlockAttrs`。
2. **嵌入块插入**使用宿主原生 `{{select * from blocks where id='<id>'}}` 语法，其中 `<id>` 只允许 `^\d{14}-[0-9a-z]{7}$`（思源块 ID 格式）已校验值，无任何用户文本拼接；SQL 的解释与执行完全在思源内核（宿主原生能力），插件不解析、不执行、不扩展该语句。此为「宿主原生结构语法」而非「插件用 SQL 查询」，边界记录于此。
3. **DOM 边界**：允许读写的 DOM 仅限——（a）插件自建 UI 树；（b）官方 `getActiveEditor()` 返回的 protyle 实例 API；（c）编辑器选区（`window.getSelection()` + 所选节点向上找 `[data-node-id]` 取当前块 ID——该属性是思源公开的块标识）。禁止依赖布局栈、页签栏内部结构、原始坐标定位菜单。

## 理由

- 需求明文禁 SQL 作为核心依赖 → 遍历/检索全部走结构化 API。
- 嵌入块若不用该语法则功能缺失（需求三.6 明确要求嵌入语义）；限定为「ID 已校验的宿主原生语法」是兼顾两者的最小开口，且与用户手写嵌入块等价。

## 后果

- 嵌入块渲染结果依赖宿主；来源块删除后宿主渲染为空/报错，插件侧同时显示「来源失效」。
- 若未来思源提供非 SQL 的按 ID 嵌入语法，应立即替换（记入 ROADMAP P4 复查项）。
