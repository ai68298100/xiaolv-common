# ADR 0007：自定义 AI 变换 = 用户指令作提示正文 + 内置同款硬边界 + 模板包真源共享

日期：2026-10-07 ｜ 状态：已采纳 ｜ 落地：R73（F7 自定义变换）、R71/R74（模板包/场景包）

## 背景

F7 要求 AI 变换"不只 5 个预设"：用户自定义指令，并可把提示词模板作为内容资产分享（定位三大场景之一）。ADR 0005 已确立 AI 硬边界（宿主模型、默认关、两级出域、原文不可变、诚实失败）。

## 决策

1. **自定义指令 = 提示正文**：`transformCustom(instruction, content)` 把用户指令作为变换提示的正文行，外层约束（"直接输出结果本体"、正文 ≤8000 字符、needContent 门禁）与内置五种**完全相同**——自定义能力不带来任何边界豁免。
2. **存储与上限**：指令存侧车 `ai.customTransforms`（≤10 条、名称 20 字、指令 500 字，逐条校验去重）；发送时机与内置一致，受「允许 AI 读取完整正文」开关管辖。
3. **菜单并列**：自定义与内置五种并列出现在动作菜单 ✦ 区；变换视图参数化（viewLabel/transformLabel 分离），「存为新条目」落变换显示名。
4. **提示词场景包走内容通道而非功能通道**：内置 10 个模板以 Markdown 包（`xlc-pack` 清单 + `xlc-item` 元数据）形态随插件发布，导入走既有 parseMarkdownPack + 策略对话框——**导入即真实思源块**，可编辑可再分享。ID 固定使重复导入幂等（跳过重复）。
5. **包清单对旧版透明**：`<!-- xlc-pack -->` 注释位于首个条目前才有效；旧解析器只认 `xlc-item`，清单天然被忽略——格式演进不破坏旧包。

## 后果

- 正面：提示词库（定位场景②）开箱即用；自定义指令把 AI 变换从"固定五按钮"变为开放能力；分享语义 = 分享活的块（与 ADR 0002 一致）。
- 代价：自定义指令质量取决于用户（插件不做提示词工程兜底，失败诚实提示）；场景包内容需随版本维护。
- 拒绝的替代方案：指令走插件内置提示词模板拼接（限制表达力）；场景包走功能硬编码（内容迭代需发版，且不可被用户修改后分享）。

## 门禁

r73-custom-transforms（归一化/截断/提示构建）+ r74（场景包完整性/快速捕获）+ settings/action-menu UI 冒烟断言。
