# ADR 0028：交互控件与异步状态闭环

## 状态

已采纳（2026-10-14，T-0054 / R201）

## 背景

搜索、动作菜单、设置/首设、捕获、变量填写和发现页面已经具备主要业务逻辑，但逐控件核对仍可能漏掉无响应入口、重复触发和失败后无恢复路径。设置页的导入、导出、重建索引和模板操作尤其需要让加载、成功、失败和空结果都可见。

## 决策

1. 每个可交互控件使用稳定的 `data-xlc-control` 标识，交互审计优先按语义 ID 定位，不依赖样式或文案。
2. 涉及数据的异步操作统一提供 idle/loading/success/error/empty 状态；loading 期间使用真实 `disabled` 和 `aria-busy` 防止重复触发，error 必须提供可读原因与 retry 入口。
3. 动作菜单文档搜索采用最后一次输入代次守卫；AI 变换捕获异常并把失败呈现在结果区域，迟到响应不得覆盖新视图。
4. 设置与首设入口采用单实例复用；嵌套的导入策略、变量填写和确认弹窗属于有意的流程层级，不能用全局弹窗数量简单判定为泄漏。
5. 清空、删除、覆盖、关闭等破坏性路径保留确认或撤销回执；表单失败保留用户输入并将错误定位到具体字段或操作状态槽。

## 证据与边界

- `pnpm run test:ix`：45/45。
- `pnpm run test:ui`、`pnpm test`：340/340、`pnpm run check`、`pnpm run build`、密钥扫描、包检查和 `git diff --check` 通过。
- `pnpm run e2e:iso`：12/12；发现隔离内核在全新工作区复跑 8/8 通过。复用旧临时工作区可能受残留数据影响，不能作为稳定证据。
- `ui-sweep` 的穷举点击器会忽略遮罩并点击底层入口，因此嵌套流程的总弹窗数告警不等于真实宿主泄漏；脚本已改为按同类宿主实例检查。
- Electron 前端、真实 AI、Android 触控/剪贴板和宿主异常仍按 B-001/B-002/B-003/B-004 现场验证。
