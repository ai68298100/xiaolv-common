# ADR 0002：思源块 = 内容唯一真源；元数据走 custom-xlc-* 块属性；侧车只存 UI 状态

日期：2026-10-06 ｜ 状态：已采纳

## 背景

需求约束：思源文档/块/资源是正文唯一来源；插件不得把完整正文偷偷复制进私有库；元数据优先用用户可见可编辑的结构；侧车数据必须可迁移、可重建。

## 决策

1. **一条目 = 库文档中的一个真实顶层块**（anchor block）：
   - text/markdown/url/asset → 段落块；code → 代码块；image → 图片块；多块结构 → superblock 包装（`{{{row ...}}}`），插入时剥壳只取子块。
   - 条目内容就是块内容（经 `getBlockKramdown` 按需取用），插件不另存正文。
2. **稳定逻辑 ID**：条目创建时生成 `xlc-` 前缀 ID（随机），写入块属性 `custom-xlc-id`。导出/导入、跨工作区恢复、provider 引用一律用逻辑 ID；块 ID 只是物理定位。
3. **元数据属性**（用户可在思源属性面板查看/编辑）：
   `custom-xlc-id / -type / -title / -alias / -tags / -category / -src-doc / -src-block / -url / -target / -created / -updated`
4. **侧车（plugin.loadData）只存**：库配置、收藏、最近使用、排序偏好、provider 注册表、UI 偏好。全部版本化（schemaVersion）+ 归一化 + 容量上限 + 损坏降级（`src/model/storage.ts`）。
5. **搜索索引**：内存构建、可丢弃、条目上限 2000、摘要截断 240 字符；不持久化全文。

## 理由

- 同步/冲突/历史回滚天然继承思源本体行为；插件删除后用户数据零损失（块还在库里）。
- 属性面板可见 → 用户可手工修补，插件可从属性完整重建侧车。
- 满足"恢复来源"：`custom-xlc-src-doc/-src-block` 打开原文档/定位原块。

## 后果

- 块属性会被思源同步，元数据跨设备一致；但属性面板写值无校验，读取侧必须归一化（已做）。
- 「条目复制到剪贴板/插入」必须现场取块内容（一次 `getBlockKramdown` 往返），离线时诚实报错，不用缓存正文兜底（缓存只有有界摘要）。
