# ADR 0036：多关键词组合检索与分词高亮契约

## 状态

已采纳（2026-10-14，T-0063 / R210）。

## 背景

在参考同类高频内容工具（Quicker 常用语、易歪歪等，参见 [`docs/research-2026-10-14.md`](../research-2026-10-14.md)）的检索习惯后，以空格分隔的多关键词组合检索是知识库与常用语调用的核心场景：
- 例如用户输入 `客服 延期`：期望匹配分类为“客服”且标题含“延期”的条目；
- 例如用户输入 `开票 专票`：期望匹配标题含“开票”且正文/标签含“专票”的条目。

既有检索模型将整串输入作为一个整体（`indexOf(rawQuery)`），当查询词含空格时，无法跨字段组合匹配，导致常见的多词检索直接返回空结果；同时，列表标题的高亮仅支持单一连续子串匹配，无法对多词分别标红。

## 决策

1. **多关键词跨字段 AND 组合检索**：
   - 查询文本按空白字符切分规范化为 `tokens = text.split(/\s+/).filter(Boolean)`；
   - **单词路径（tokens.length === 1）**：保持既有快速路径与整串精确加权逻辑不变，确保性能与已有行为 100% 稳定兼容；
   - **多词路径（tokens.length > 1）**：
     - 执行严格的 **AND 语义**：条目必须匹配全部 token（每个 token 在标题、别名、标签、分类、摘要、拼音任一字段中的匹配得分必须大于 0）；
     - 任一 token 未命中任何字段，条目即判定不匹配并返回 `null`；
     - 全部 token 均命中时，总得分为各个 token 得分之和，使多字段深度匹配的条目排在更前面；
     - 若所有 token 命中了同一字段，则 `matchedBy` 继承该字段，若命中跨不同字段则为 `"multi"`。
2. **列表分词安全高亮（Multi-token Highlighting）**：
   - 收集全部 token 在标题中的匹配位置区间 `[start, end)`；
   - 将所有重叠或相邻的匹配区间进行排序合并（Merge Intervals）；
   - 按切分后的文本片段交替生成普通文本节点与 `<mark class="xlc-hit">`，严格使用 `textContent`，绝不注入 `innerHTML`。

## 验证与边界

- 单元测试覆盖多关键词同字段命中、跨字段（如标题+分类）组合命中、部分词未命中严格排除、打分累加与稳定性；
- 负向门禁测试验证任一缺失词的严格 AND 阻断；
- 生产 UI 冒烟测试断言多关键词搜索下的列表渲染与高亮表现。
