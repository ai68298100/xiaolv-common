# ADR 0058：多块回包假设更正与写前保守限制

日期：2026-10-18（2026-10-19 修订） ｜ 状态：已采纳（单行结构块拦截与代码围栏空白清洗已加固；宿主验收仍受 B-005 阻塞） ｜ 任务：T-0091–T-0092 / R238–R239, T-0102 / R249

## 依据与更正

ADR 0057 把 `doOperations[].id` 当作全部新物理块的清单，依据不足，现撤回该决策与“完整止损”结论。固定上游 v3.8.6 commit `158812497497c6fa8a6d1031bfa2f025a61ee5c2` 的源码表明：

- [`appendBlock`](https://github.com/siyuan-note/siyuan/blob/158812497497c6fa8a6d1031bfa2f025a61ee5c2/kernel/api/block_op.go#L482) 只构造一个 `appendInsert` 操作；[`doAppendInsert`](https://github.com/siyuan-note/siyuan/blob/158812497497c6fa8a6d1031bfa2f025a61ee5c2/kernel/model/transaction.go#L1080) 插入全部顶层节点后，仅把原操作 ID 设为首节点（L1156）。一个操作可能对应多个兄弟块。
- [`normalizeListMindmapMetadata`](https://github.com/siyuan-note/siyuan/blob/158812497497c6fa8a6d1031bfa2f025a61ee5c2/kernel/model/transaction_list_mindmap.go#L192) 遍历整文档，可能为已有节点追加 `setAttrs` 操作（L224）。不能把这些 ID 当成新条目的部分，尤其不能在失败时据此删除。
- [`normalizeBlockUpdateTree`](https://github.com/siyuan-note/siyuan/blob/158812497497c6fa8a6d1031bfa2f025a61ee5c2/kernel/model/block_update.go#L225) 只保留选中的 `firstContentBlock`。单块改成多段也可能成功返回却遗漏尾段。

这是固定版本源码证据，不是本轮真实内核或 Electron 验收。历史脚本“每块一条操作”的注释及受控多操作夹具不能证明实际响应完整。

## 决策

1. 新建、正文更新和导入写前采用受限格式：单行内容，或一个完整且无尾随正文的代码围栏。拒绝其他多行、结构标记、物理 IAL、空正文和超限正文；不通过截断把不完整正文交给宿主。这是保守格式边界，不是通用 Markdown 解析器或宿主验证。
2. `appendBlock` 只识别 `action=insert` 且 `parentID` 等于目标文档的合法 ID。`setAttrs` 不作为新块；未知操作、父块不符或意外多 insert 返回“结果待核对”，提示打开库文档，不盲删响应中的 ID。停止创建新的 `custom-xlc-parts`。
3. 读取已有 parts 前，现场 `getChildBlocks` 核对锚块和全部部分是原文档连续顶层块；批量属性必须完整，锚块身份和清单相符，尾块不能另带逻辑 ID/parts。此检查限制读取范围，不证明历史正文完整。
4. 带多 parts 条目的正文更新、普通删除和批次撤销均暂停。缺乏独立的所有权证据时，不以“同库、存在、相邻”授权自动删除。
5. 单锚块的存储正文读取、更新和删除也重新核对原文档成员关系，避免陈旧索引继续读改已经移出库的块。
6. 覆盖导入在删除旧条目前检查新正文和旧正文备份都符合当前写入边界，避免恢复路径被新限制阻断。跳过重复策略保持跳过，不因正文受限而写入。
7. 捕获提示覆盖所有条目类型，帮助和模板入口明确限制。原 20 条模板的多行部分会被拒绝；当前示例包扩展为 25 条，其中新增邮箱、地址、无效身份占位、网址和 JSON 五条符合边界的安全示例，其余多行模板仍会拒绝；复杂示例与真实资源安装继续后置。
8. 捕获入口拒绝超限内容，不先截断再交给服务；表单在正文旁显示拒绝原因并保留输入。块引用捕获使用真实目标的单行引用语法，避免空正文被写前保护拒绝。编辑正文也先验证旧正文可读取且能按当前限制恢复，再写元数据。

## 验收与剩余边界

服务契约覆盖写前零请求、单行/代码围栏对照、尾随正文/缩进伪围栏、超限拒绝、已有块 setAttrs、错误 parent、parts 跨文档/乱序/夹杂/独立条目/缺属性、缓存锚块移出库、导入覆盖及具体失败行，续作覆盖六个捕获入口、引用标记与编辑备份前置；示例包契约覆盖 25 条解析、8 条可写、导入 8/17 回执、重复跳过及复制/插入类型载荷。全套单元 512/512；浏览器检查全部8类型提示与生产语言文件一致，多行正文不调用创建且保留字段错误/焦点。新增门禁实际注入源码违规后失败，恢复原字节后通过。负向清单及日志见当期账本 R238/R239。

2026-10-19（T-0102 / R249）补充单行纯函数级边界加固：单行写前拦截引用块 `>`、列表项、任务列表、表格行 `|`、水平分隔线及超级块/折叠分界 `{{{`/`}}}`，杜绝单行被思源内核隐式展开为嵌套容器块；代码围栏首尾支持含空格/制表符的空白行安全清洗。独立专项测试 `tests/kramdown-restriction.test.cjs` 与全量单元 530/530 通过，并完成负向注入验证。

B-006 仍开放。后续须在满足 B-005 的环境核验宿主解析、回包 DOM/AST 顶层节点、读回、结构、更新和恢复，才能替换当前限制。历史无清单条目不推断相邻归属；本轮不扫描用户库，不修复或删除其历史尾块。请求与最终读写之间仍不是宿主原子事务，不能宣称消除了所有外部并发编辑竞态。
