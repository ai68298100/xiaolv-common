# ADR 0051：编辑器目标与动作回执

## 状态

已接受，T-0081 / R228（2026-10-16）。

## 问题

无活动编辑器和失效插入位置已实现复制降级，但此前缺少真实 Electron 现场证据。预览主按钮在执行前复用了“已复制”的成功回执文案；移动端待验证提示的优先级还高于复制失败，可能把失败显示成成功。连续插入引用、嵌入和源正文时，宿主选区可能停留在不可编辑的渲染节点，不能只凭编辑器存在就承诺能够插入。

## 计划与边界

- 操作前显示将要发生的行为，操作后才显示实际成功回执；复制失败先显示失败原因，再考虑能力待验证说明。
- 保留打开弹窗时的编辑器与位置，不将失效目标改投后来激活的其他文档。只使用公开编辑器 API 和标准选区能力核验，不读取私有布局或猜测插入位置。
- 在可销毁 Electron 副本中通过真实页签关闭形成无活动编辑器状态，验证主动作提示、系统剪贴板、协议回执和文档未被写入；复制失败使用执行层和真实装配测试，不伪造系统权限失败。
- 同一目标文档连续执行引用、嵌入、源正文并读回内核；先记录可复现行为，再决定是否存在官方 API 范围内的安全修复。禁止自动重试已经可能写入的动作或伪造插入成功。
- 新增或修改门禁执行真实违规注入、恢复原字节和正向复验。Android 和真实 AI 未现场验证的限制继续保留。

最终方案、验收范围和取舍随现场证据更新，详细过程记录在当期账本。

## 结果

- 执行器在异步读取正文前冻结编辑器目标；弹窗持有的 tracked range 由弹窗生命周期管理，执行器自行捕获的句柄等待执行完成后在 `finally` 释放。
- `rootID`、`disabled`、`isConnected`、tracked range 状态和祖先节点关系共同决定目标是否可写；目标失效时复制到剪贴板，绝不重新读取后来激活的编辑器。
- 前置提示使用“将要发生的动作”，实际回执优先报告失败；移动端待验证说明不会覆盖 `copy-failed`。
- `pnpm test` 457/457、`test:ix` 74/74；提示、目标冻结、rootID/disabled/connected 保护和回执优先级的违规注入均准确失败，恢复后正向复验通过。
- 固定思源 3.8.7 / Electron 44.7.0 隔离副本最终 7/7。独立验证同一搜索窗口的冻结目标：插入一次后真实关闭 A、打开来源 B，原输入框节点保持；再次主操作复制降级，A/B 子块完整 Kramdown 的立即及延迟快照不变。连续协议动作另行记录：引用和嵌入落块，紧接源正文因宿主选区不可用而复制；不将该分支宣称为第三次插入通过。
