# ADR 0041：高频多音词拼音检索修正与智能注音契约

## 状态

已采纳（2026-10-15，T-0068 / R215）。

## 背景

在小驴常用的核心应用场景（商务沟通、财务发票、技术研发、客服支持）中，高频词汇包含大量汉字多音字：
- 商务财务场景：“银行 / 开户行”（应为 `hang`，单字库常误为 `xing`）、“会计”（应为 `kuai`，常误为 `hui`）、“行业”（应为 `hang`，常误为 `xing`）；
- 研发写作场景：“重新 / 重试”（应为 `chong`，常误为 `zhong`）、“调整 / 调试”（应为 `tiao`，常误为 `diao`）；
- 常用交互场景：“长按 / 长度”（应为 `chang`，常误为 `zhang`）、“成长 / 行长”（应为 `zhang`，常误为 `chang`）。

由于单字级拼音库缺乏上下文词组感知，容易选择默认首读音，导致用户按真实发音搜索（如用 `yh` 搜“银行”、用 `cx` 搜“重新”、用 `kj` 搜“会计”）时索引无法命中，且拼音字符级高亮定位出现偏差。

## 决策

1. **轻量内置高频多音词词表（Zero-dependency Dictionary）**：
   - 在 `pinyin-tiny.ts` 内置涵盖商务、财务、客服、写作常用多音词的紧凑拼音映射表；
   - 不引入外部重型 NLP/分词包，不增加打包体积负担（增量 < 1 KiB）；
2. **词组优先滑动注音引擎（Phrase-first Phonetic Scanner）**：
   - 统一抽象底层字符级拼音解析器：在遍历字符串时，优先贪婪前瞻匹配多音词表；
   - 若命中词组，词组内部汉字精准使用词表指定的拼音与声母；
   - 未在多音词表中的单字，回退至基础单字库转换；
3. **索引构建与高亮定位双向同步**：
   - 条目索引构建（`annotate`，生成 `py` 与 `pyi`）与搜索高亮（`findPinyinMatches`）共用底层解析器，确保索引检索与字符标红 100% 吻合一致；
4. **性能与降级**：
   - 扫描在有界文本（标题与别名截断长度内）中执行，耗时控制在微秒级；
   - 环境不支持拼音库时无缝降级为 noop 适配器。

## 验证与边界

- 单元测试覆盖“开户银行”、“重新评估”、“财务会计”、“调整参数”、“长按条目”等典型多音词的首字母与全拼索引断言，以及对应的高亮区间提取；
- 负向门禁测试确保断言有效性；
- 全套 UI 冒烟测试与包规范检查通过。
