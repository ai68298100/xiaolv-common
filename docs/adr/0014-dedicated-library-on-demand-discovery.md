# ADR 0014：专用内容库与按需发现分离

日期：2026-10-11 ｜ 状态：已接受 ｜ 任务：T-0032

## 背景

用户已有大量思源笔记，但不希望为了使用小驴常用重新录入全部内容。直接把所有笔记本改成默认常用库会把普通笔记、草稿和隐私内容混入搜索，并改变条目删除、编辑、来源和使用统计的语义。当前 `notebook` 模式本身也只是索引所选笔记本根文档中的已标记条目，不是全笔记全文索引。

同时，插件已经有选区、当前块、整篇文档、剪贴板、链接/图片/块引用右键、工具栏、命令面板和定向插入入口，但动作名称和目标提示分散，用户很难判断“如何快速增加”和“会插入到哪里”。

## 决策

1. 保留专用内容库作为唯一默认工作集和写入目标。它负责主搜索、分类、收藏、最近使用、使用次数、变量、模板、AI 语义找和 provider 聚合。
2. 新增按需发现层。发现是用户主动触发的、只读的、可取消的临时会话；候选不进入主索引、侧车、收藏、最近、使用计数、AI 或 provider。
3. 发现候选经用户确认后复制到专用库，生成新的逻辑 ID，保留 `sourceDocId/sourceBlockId` 回链。原文不改，副本不自动同步原文。
4. 来源块 ID 是可靠的同源去重依据；完整正文规范化相同只能作为“内容相同”提示；标题或摘要相同只能作为“可能重复”提示。所有重复提示都允许用户覆盖。
5. 阶段一先统一跨页面收录/插入入口和目标语义；阶段二实现当前文档/当前笔记本发现与批量收录；阶段三再开放指定文档树、指定笔记本和全部笔记本，并加入独立限额、进度、取消、隐私和压力验收。
6. “保存整篇文档为条目”和“从当前文档发现”是两个独立动作。前者产生一个整篇 Markdown 条目，后者只产生候选，不自动写入。
7. 删除常用库副本不删除来源笔记。批量收录的撤销只能安全删除本批次新建且未被用户继续编辑的副本；其他情况报告跳过，不承诺强制回滚。

## 后果

- 默认搜索保持快速、干净、可预测；用户仍可通过显式发现利用已有笔记。
- 发现功能需要独立的候选模型、扫描限制、进度状态、部分失败回执和去重提示，不能简单复用专用库索引。
- 收录后存在“原文”和“库内副本”两个真实块，产品必须显示来源路径、来源失效和“不自动同步”语义。
- 全局发现的性能和隐私成本由用户主动选择范围承担；插件不在后台扫描整个工作区。
- 现有 `doc/tree/notebook` 配置和协议保持兼容，不需要把普通笔记属性改造成常用条目。

## 阶段二实现补充（2026-10-11）

- 当前笔记本通过当前文档 `getBlockInfo.box` 定位；发现会话继续复用当前文档发现服务，范围仅扩展到该笔记本的文档树，扫描上限为 200 篇文档和 2000 个块。
- 关闭会话或卸载时以代次令牌作废在途扫描；用户主动停止则等待已发出的内核请求（包括并发请求）完成、不再启动新请求，并保留已完整扫描文档的候选。无法确认专用库边界时 fail-closed。候选仍只保存在内存，候选正文按预览读取，不自动收录。
- 批量收录以批次授权记录条目身份、属性和原始正文；撤销先重建库索引，再对属性和正文做两次现场核验，只删除未被编辑且仍在配置库中的副本。
- `appendBlock` 会按 Kramdown 中的嵌套块结构解析 IAL。复制前移除所有块物理 `id`、块更新时间和继承的 `custom-xlc-*` 元数据，同时保留样式等普通块属性；代码围栏及行内代码中的 IAL 字面文本不改写。来源文档/块回链写在新副本根块属性。
- 该 IAL 规则作为收录、重复内容比较和批量安全撤销共享的规范化边界。真实内核验收覆盖嵌套列表复制产生新物理 ID、回链保留及撤销后原文/原嵌套块仍存在。

阶段三实现记录（T-0036 / R183）：指定文档树、指定笔记本和经二次确认的全部笔记本已开放为按需范围；独立预算、100 条分页、部分失败保留、候选范围复核和停止后保留已完成文档候选均已实现。停止会等待已发出的内核请求完成，并阻止后续请求；宿主请求本身不能取消，且已并发发出的请求都会结束后才返回。超时后标记不完整，未核验重复状态的候选仍须在收录前重新检查。阶段三自动化验收不替代思源 Electron/Android 现场验证，沿用 B-001/B-002。

## 生命周期补充（2026-10-11）

- 显式关闭会话会先停止新收录。若 `createItem` 已开始，关闭返回 `conflict` 并保留会话和撤销批次；收录回执到达后，调用方可以先撤销，再次关闭。关闭冲突期间新扫描不能覆盖该会话。
- 插件卸载时先同步关闭扫描和写入入口，等待在途创建并仅对卸载时仍在执行、且已知创建成功的当前条目使用同一批次令牌做条件删除。已经正常返回收录回执的条目不纳入卸载补偿。
- 卸载 hook 最多等待 4 秒，为思源类型声明中的共享 5 秒生命周期预算留出宿主余量。已知删除、跳过、失败和无法确认结果均记录；等待超时会立即诊断，未完成的 Promise 仍可能在宿主拆除后继续，随后结果通过迟到日志报告。
- `siyuan` 类型声明允许 `onunload(): Promise<void>` 并记载共享预算；目标思源 Electron 运行时是否等待该 Promise 尚未现场验证，不能把有界等待描述成必然完成。继续按 B-001 标记。

## 范围目标切换与恢复（T-0037 / R184，2026-10-11）

- 文档树搜索词变化即作废已选根文档、清除旧结果并禁用扫描；每次异步搜索使用请求代次，过期结果不得覆盖当前查询。搜索结果出现后使用未选择占位项，用户明确选择根文档后才可开始扫描。
- 指定笔记本列表分别表达加载中、加载失败、重试和成功但为空。失败保留原因并提供就地重试；空列表不冒充候选过滤为空。界面提示以“扫描目标”为语义，避免把已选范围误报为未选择范围。
- 以上仅约束发现弹窗的临时选择状态，不改变发现会话数据、专用库边界或写入语义；Chromium/隔离内核验证不替代 Electron/Android 现场验收。

## 文档树入口目标冻结（T-0038 / R185，2026-10-11）

- 文档树右键“从此文档发现常用语”只适用于公开事件 `doc` 或恰好单项的 `docs` 选择；笔记本、混合未知类型、多选和非法块 ID 不作为树根。入口读取事件 `items` 中结构化的文档 ID/路径快照，不以活动编辑器或私有 DOM 推断扫描目标。
- 发现面板以该文档树为初始范围并立即扫描冻结根；显示根路径，用户后续主动搜索其他根时仍须重新选择。异步路径查询完成后若插件正在卸载，则不打开弹窗。
- 本决策只增加一个已有 `discoverTree` 能力的用户入口，不扩展服务范围、预算或写入语义。事件类型参考本仓库 `siyuan` 1.2.9 公共声明；Electron 菜单和 Android 行为仍需真实宿主验证。

## 发现候选的分类（T-0039 / R186，2026-10-11）

- 发现候选仍只存在当前会话；分类只在用户确认复制到专用库时写入新块，不回写来源文档。
- 新收录缺省分类为“待整理”，便于用户稍后从主库分类检索并批量整理。面板允许修改本次默认分类；预览中的单候选覆盖优先于默认值，并可恢复跟随默认。
- 服务协议允许显式传空字符串表示不分类；只有未提供分类时才使用“待整理”。分类不改变同源/正文重复判断、来源边界或批次撤销语义。

## 不采用的方案

- **不把全部笔记本直接变成默认库**：噪声、隐私、性能和删除语义风险过高。
- **不首版做原地收录**：直接给原笔记块写 `custom-xlc-*` 会让当前删除动作存在误删风险，嵌套块、移动块和取消收录也需要全新语义。
- **不做后台全文索引**：会增加启动成本和隐私不确定性，也无法替代用户对“什么值得成为常用语”的判断。
