# ADR 0059：Issue #1 独立笔记本创建方案

日期：2026-10-18（2026-10-19 修订） ｜ 状态：离线内核契约、服务编排与 UI 两步/补偿凭据已实现（9/9 smoke 通过），真实宿主验收待沙箱环境具备 ｜ 任务：T-0094 / R241, T-0101 / R248

## 背景

GitHub Issue #1 要求在选择内容库时直接新建一个独立笔记本，同时保留当前“在已有笔记本中新建专用库文档”的路径。当前设置向导只能列出已有笔记本，创建新文档后把库落在该笔记本中；因此 issue 仍然开放，不能把现有“新建专用库文档”描述成已解决独立笔记本创建。

## 决策

本轮先实现离线契约与服务编排；UI 接线和真实宿主验收仍后置。独立的“新建专用笔记本”模式不改变现有 `doc`、`tree`、`notebook` 配置语义：

1. 在首设和更改内容库选择器中增加互斥模式“新建专用笔记本”，字段为笔记本名称和库文档名称；默认仍推荐“新建专用库文档”，避免升级后静默创建容器。
2. 内核客户端增加显式 `createNotebook` / `removeNotebook` 能力，服务层通过 `createIndependentLibrary` 先创建笔记本，再用返回的笔记本 ID 创建库文档；两步都返回 `Receipt`，不把未知结果当成成功。
3. 创建文档失败时尝试删除本次刚创建且仍为空的笔记本；删除失败必须在 UI 回执中保留笔记本 ID，不能声称已回滚。创建成功后配置落为 `mode: "doc"`、`containerDocIds: [docId]`、`createdDocIds: [docId]`，并记录 notebook ID 供设置页显示和后续清理审计。
4. 重复点击通过 revision、busy 状态和幂等键保护；名称校验、笔记本列表加载、权限失败、超时、空名称和文档创建失败均就地显示，失败时不写入半成品配置。

## 验收边界

- 模型：`normalizeLibraryConfig`、迁移和序列化兼容旧配置；新增字段只接受合法思源笔记本 ID，未知/未来版本拒绝并保留现配置。
- 服务：create notebook → create library doc 的成功、笔记本创建失败、文档创建失败、补偿删除成功/失败、重复调用和超时均有单测；负向注入必须失败，恢复源码后全套测试通过。
- UI：桌面与窄屏均显示模式、名称字段、加载/禁用/保存中/成功/失败/补偿失败状态；设置重开能显示已创建笔记本与库文档路径；“稍后再说”不创建任何资源。
- 宿主：离线桩和隔离内核只证明协议编排，不能替代真实思源 Electron/Android 权限与生命周期验收。B-005 解除前不启动新的宿主实验。

## 非目标

本轮不实现按分类自动建立多个文档、不迁移已有库、不自动删除用户手动创建的笔记本，也不发送 GitHub issue 评论或 PR。Issue #1 在真实宿主验收与发布前仍保持开放。
