# ADR 0045：单条条目使用频次重置与侧车治理契约

## 状态

已采纳（2026-10-15，T-0072 / R219）。

## 背景

自 R67 引入使用计数与「常用」智能排序（`sort: "frequent"`）以来，条目在每次插入或复制成功后会自动增加使用计数，用于在按频次排序时优先置顶高频条目。
然而既有实现仅在完整设置面板中提供了全局清空（`clearUsageBtn`，将全库所有条目的使用计数一次性抹除）。
在真实工作流中：
1. 用户在测试新模板、或在某个短期突发项目（如短期促销、集中活动申报）中高频调用了某条条目，导致其计数偏高；
2. 项目结束后，该条目在「常用」排序下长期滞留在首位，干扰了用户日常高频条目的调用；
3. 用户为了清理这单一一项，被迫牺牲全部条目长期积累的真实使用数据去执行“清空全部统计”。

## 决策

1. **单条条目使用计数重置 API**：
   - 在插件核心状态服务提供 `resetItemUsage(itemId: string): boolean`；
   - 若侧车字典 `this.state.usage[itemId]` 存在，执行安全删除并触发异步落盘 `this.persistSoon()`，返回 `true`；若原本无记录则返回 `false`；
2. **条目动作菜单入口与动态可见性**：
   - 在主搜索面板与详情动作菜单中，当且仅当当前选中条目的使用计数大于 0（`useCount > 0`）时，动态呈现操作项：
     `↺ 重置使用频次（当前 %s 次）`（英文：`↺ Reset usage count (%s)`）；
   - 使用计数为 0 的条目不展示该项，保持菜单紧凑；
3. **即时重查与排序自然下移**：
   - 触发重置后，即时给出反馈提示（`已重置「%s」的使用频次`）；
   - 自动重新计算当前弹窗内的使用计数快照并触发 `refreshPreservingPosition()`；若当前正处于「使用频次」排序，该条目将自然下移回退至 0 次对应位置，界面即时响应；
4. **数据真源与隐私保护**：
   - 使用计数纯本地保存在插件侧车配置中，重置操作不触碰思源文档与真实块数据，零数据丢失风险。

## 验证与边界

- 单元测试覆盖单条重置对有效条目、无效条目、空字典的判定及侧车数据清理；
- 生产 UI 交互审计验证在动作菜单中触发重置后，条目计数清零且列表即时响应；
- 移动端动作菜单同步支持该操作。
