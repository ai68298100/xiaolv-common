# ADR 0023：捕获 AI 失败恢复态

- 状态：接受
- 日期：2026-10-13
- 关联：T-0049 / R196 / ADR 0022

## 背景

捕获页 AI 整理和草稿失败目前只调用通用通知。通知消失后，表单没有保留错误原因或明确重试入口；虽可再次点击原操作按钮，但用户需要自行推断恢复方式。原型的 AI 状态板也没有表现失败和恢复。

## 决策

1. 整理与草稿分别在各自操作附近显示行内失败说明和“重试”按钮，并使用 `role="alert"`/`aria-live="assertive"` 暴露异步失败。
2. 点击重试复用原有生产操作处理器，整理重读当前正文，草稿重读当前描述；请求开始时隐藏旧错误，忙态继续由原操作按钮禁用并更新文案。
3. 成功后呈现既有建议/草稿结果；关闭表单后递增请求代次，迟到响应不更新任何表单状态。
4. 用可控 harness 失败桩验证失败、重试和关窗竞态；这些证据不替代真实模型、超时策略或 Electron 生命周期验证。

## 取舍

- 错误就地保留，避免只靠会消失的 toast；重试入口只在失败后出现，避免表单常态增加多余按钮。
- 失败后不自动重试，不改变模型出域授权或内容；用户可修改输入后点击重试。
- 本 ADR 不定义统一网络请求服务或超时取消，它们仍是独立架构欠项。

## 验证

- `test:ui` 应触发整理/草稿失败、检查错误语义及重试控件、点击后成功，并检查忙态时真实 `disabled` 锁。
- 关闭后迟到响应应能证明重新打开的表单没有建议/草稿污染。
- 新增行为断言需负向验证；文档原型样例只作为静态视觉镜像，生产行为以 smoke 为证。

## 未决

- 思源宿主 AI 是否返回超时、取消和关窗回调仍待 Electron 现场验证（B-001）。
- 调用错误映射的细节和模型配置指引沿用现有 `aiErrorText`；不在 UI 层解释未验证的宿主错误结构。
