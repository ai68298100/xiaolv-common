# ADR 0017：原型与局部设计 token 作为 UI 事实源

- 状态：接受
- 日期：2026-10-12
- 关联：T-0042 / R189

## 背景

R187 将生产界面迁移到小驴闪卡 R54 的淡薰衣草色板，R188 又调整了导语层级、表单滚动、详情动作区、菜单边界和首次设置密度。原型 `prototype.html` 虽然补充了状态镜像，但规范板仍保留早期蓝色样例；状态卡中还出现“查看详情”等并非通用生产反馈的占位承诺。与此同时，生产 SCSS 的字号、行高、间距和圆角仍多处直接写数值，设计规范宣称的统一阶梯与实际文件不符。

## 决策

1. `docs/design/prototype.html` 是 UI 唯一视觉事实源。`prototype-r187.html` 仅保留为历史工作流快照，不再覆盖现行状态。
2. 原型 screen 0 展示当前生产色板和 token 角色；状态镜像最初位于 screen 9，后由 R195 顺延为 screen 11。现行 screen 11 是视觉/交互状态样例，必须注明静态样例与生产证据的边界。
3. 颜色、字号、行高、间距、圆角、阴影、层级和动效时长集中在插件局部 `tokens-r187.scss`。布局宽高和断点仍可按内容作为几何常量。
4. 组件清单只对有源码或测试证据的交互作事实描述；未来契约/待宿主验证项单独标记，不以原型截图推定已实现。
5. UI 视觉变化按 `prototype.html → production screenshots/smoke → component catalog` 同步。先改原型与 token，再实现/核对生产 DOM；交付时重渲染原型和生产截图。

## 取舍

- `prototype.html` 仍以静态 HTML/CSS 为主，不把整个插件逻辑复制成第二套实现；状态流正确性由服务、UI smoke、交互审计和宿主 E2E 负责。
- 为保持当前渲染尺寸，本轮只把已存在的 CSS 数值提为语义变量，没有统一所有布局尺寸，也没有把每个 CSS 声明强制压成主 4px 栅格。
- 组件目录中明确列出自动化、隔离内核和真实宿主的证据级别，牺牲一些“全覆盖”措辞以保留可验证性。

## 验证

- 对本轮开始时 HEAD 与工作区 `src/styles/index.scss` 做同口径正则扫描：字号/行高/字重数值字面量 148→0；间距属性（padding/margin/gap）命名 token 覆盖 0/188→195/200；圆角数值字面量 24→0。后续解析 token 定义发现字号唯一值数量未减少，已用间距值有 24 个、其中 9 个符合 4px 网格；因此这是变量覆盖证据，不是完整尺度收敛证据。布局几何值不计入间距扫描。
- 收尾复核清除重复的 `space-1..4` 声明、冲突的 `space-5/6` 覆写和重复 10px 圆角别名，保持使用点的计算值不变；原型修正窄屏预览行为、未实现的全文提示和不存在的成功跳转。
- 生产 `pnpm run check`、`pnpm run build`、`pnpm run test:ui` 通过；完整门禁由本轮账本记录。
- `node scripts/render-prototype.cjs` 生成权威原型截图并目视对照；`prototype-r187.html` 不更新。
- `docs/acceptance-audit-2026-10-12.md` 记录全套自动化和内核回归，以及保留的宿主待验和未实现架构项。

## 未决

- Electron 插件运行时、Android 触控/剪贴板及宿主设置极端序列异常仍按 `BLOCKERS.md` B-001 至 B-004 跟踪。
- 原型与清单目前不提供自动从生产 DOM 生成规范的机制；需要新增组件时，开发者按本 ADR 同步更新并运行相应门禁。

## 后续修订

- R195 将发现页加入 screen 10，并把状态镜像从 screen 9 顺延到 screen 11；R196/R197 又补入 AI 失败重试、移动端选中与捕获字段顺序。现行编号和状态以 `docs/design/design-spec.md` 与 `prototype.html` 为准，保留本 ADR 的历史决策语义。
