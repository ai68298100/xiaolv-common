# ADR 0029：服务层写入一致性与请求治理

## 状态

已采纳（2026-10-14，T-0055 / R202）。

## 背景

界面层已经为主要按钮补了 busy 锁、失败提示和重试入口，但协议调用、快捷键、重复弹窗和网络重试都可能绕过 UI。单靠按钮状态不能保证不会重复创建块、重复追加文档或让迟到响应覆盖新结果。写入失败还可能留下“属性已变、正文未变”或“旧块已删、新块未建”的半完成状态。

## 决策

1. `LibraryService` 的写操作按逻辑 ID、物理条目、目标文档或批次串行。创建、更新、删除、文档追加和首次建库接受受限长度的幂等键；成功回执在实例内有界缓存，失败不缓存，允许修正后重试。
2. Discovery 按来源块 ID 串行收录，覆盖跨发现会话的竞态；关闭会话在进入等待队列前快速失败。导入入口按 `LibraryService` 串行，覆盖导入先读取旧正文，类型变化时创建失败会尝试恢复旧条目，空正文快照也必须恢复。
3. 更新属性与正文前读取快照。任一步失败都尝试恢复；恢复失败时回执必须明确说明状态可能部分更新，不能伪装成普通失败。导入完成后的索引刷新失败保留逐条写入结果，以 `reindexError` 让 UI 提供重试/刷新入口。
4. 内核读取请求统一使用在途去重、`latest + raceKey` 竞态取消、超时取消和网络限次重试；写端点默认不重试。搜索文档已接入 latest/raceKey。鉴权/权限失败通过统一回调清理缓存和当前 UI，登录跳转仅在宿主提供公开能力时执行。
5. 成功写入统一失效可丢弃索引，并通过条目 ID 精确清理预览缓存；预览异步回填带 generation 和 in-flight 去重，旧正文不会覆盖新正文。主搜索/发现列表已有窗口化渲染；继续扩大虚拟列表前必须有真实基线证据。

## 取舍与边界

- 幂等回执只在当前插件服务实例内保存，重启后依赖稳定逻辑 ID 或宿主端幂等能力；不把内存缓存当数据真源。
- 文档追加默认允许用户有意插入相同内容，只有提供幂等键时才去重；不同目标文档的幂等键不会互相吞写入。
- 没有宿主公开登录页/回跳 API 时不伪造登录行为；仅清理失效状态并给出可读提示。Electron、真实 AI、Android 触控/剪贴板和 B-004 宿主异常仍需现场验证。
- 性能基线显示主列表当前最多约 100 行；在没有滚动帧率、首屏时间或内存收益证据时，不继续增加复杂虚拟滚动或字体子集化改造。
