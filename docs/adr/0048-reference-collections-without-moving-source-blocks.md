# ADR 0048：不搬迁源块的常用集合与引用入口

## 状态

已采纳（2026-10-15，T-0075 / R222；实现随 T-0076 / R223 收口，Electron/Android 仍待现场验证）

## 背景

用户在已有笔记中积累了大量可复用句子、段落和模板，但不希望把它们全部搬到专用“常用语”文档。竞品调研显示，主流 GUI 更常用“独立条目 + 搜索/标签/分组”；PhraseExpress 进一步支持链接条目，让同一原文出现在多个文件夹而只保存一份。小驴常用当前的按需发现会在收录时创建专用库条目，`blockref` 条目则主要表达插入思源引用，两者都没有完整覆盖“原块留在原处、仍能像常用语一样搜索并读取原文”的工作流。

## 决策

采用两级模型，先实现低风险的标签视图，再评估持久化引用入口：

1. **源块不动**：思源原块继续是正文唯一真源；标签、分类和别名仍写在用户可见的块属性中。插件侧车不保存正文，也不作为引用关系的唯一存储。
2. **标签视图优先**：用户选择文档、文档树或笔记本范围后，用一个或多个指定标签发现候选块。扫描有界、可取消、可见回执；结果可预览但不自动写入专用库。
3. **引用入口作为后续能力**：用户确认“加入常用”后，在专用库创建轻量引用记录，至少保存 `sourceDocId`、`sourceBlockId`、显示标题和用户元数据；正文域为空或明确标识为快照，不得静默复制为第二真源。引用记录删除只解除入口，不删除源块。
4. **调用时重新读取**：搜索结果展示标题/摘要可以使用有界缓存，但预览、复制和插入前必须读取源块；读取失败显示来源失效，不静默使用旧正文。源块更新后下一次调用应反映新内容。
5. **动作语义分开**：引用入口至少区分“插入源内容”“插入思源块引用”“打开来源”。不能把 blockref 的现有“插入引用语法”误认为已支持“直接插入源内容”。
6. **不做无边界全库监听**：首版只扫描用户明确选择的范围和标签；不监听前台应用，不做全局热字符串替换，不依赖 SQL 查询。

## 数据与兼容约束

- 优先复用现有 `sourceDocId/sourceBlockId` 与 `custom-xlc-*` 属性；如需区分引用记录，新增明确的版本化类型/属性并提供迁移和导出导入规则。
- 引用记录必须能被 `checkBlocksExist` 检测来源状态，且库条目自身与来源块的删除、移动、冲突状态可区分。
- 搜索索引中的摘要、拼音和标签属于可重建缓存；不能因为缓存存在而跳过调用前的源块读取。
- 任何新门禁必须做负向验证：注入失效来源、错误标签或旧正文缓存后，测试应确认失败/降级路径可见，再恢复通过。

## 取舍

- 标签视图的优点是几乎零迁移成本，缺点是每次发现都要扫描选定范围，且不能形成手工排序的精选清单。
- 引用入口能形成稳定的常用集合、收藏和跨场景排序，代价是需要新增引用记录模型、去重、实时读取和失效治理。
- 直接使用思源双链语法可以保留块语义，但双链本身不是可搜索的条目元数据；因此需要引用记录或可重建视图承载标题、标签和类别。
- 继续复制正文实现简单但会制造第二真源，与项目不可回退约束冲突，本 ADR 不采用。

## 验收边界

隔离内核 3.8.7 已确认 `batchGetBlockAttrs` 与 `getBlockKramdowns({ids, mode:"textmark"})` 的响应形状；生产代码已接入有界标签筛选、引用入口、实时源块读取和独立的源正文插入动作。该证据只覆盖内核 API 形状，不等于 Electron 壳、Android 触控或真实宿主现场验收；这些仍按 B-001/B-002 保持待验证。
