# ADR 0057：多块条目的锚块 parts 清单与保守降级

日期：2026-10-18 ｜ 状态：已采纳（待真实宿主验收） ｜ 任务：T-0090 / R237

## 背景

思源 `appendBlock` 可以把一段 Markdown 返回为多个兄弟块。旧实现只给首块写 `custom-xlc-*` 属性，因此预览、复制、导出和删除都可能只覆盖首块，尾块留在库文档中。当前 B-005 阻止启动新的真实 Electron/思源实验，不能用受控假内核或未经核对的 superblock 字符串宣称已完成根治。

## 决策

1. 新建条目时收集同一次 `appendBlock` 回包中的全部合法物理块 ID，首块继续作为条目锚点；多块条目在锚块写入 `custom-xlc-parts`，按回包顺序用逗号保存。
2. 正文读取、索引摘要、复制/导出、条件撤销和删除按该清单逐块处理，并以空行拼接正文。旧条目没有 `custom-xlc-parts` 时只读锚块，禁止依据相邻块猜测归属。
3. `parts` 缺失、重复、顺序首块不匹配、含非法 ID 或超过 64 块时，读写以 `conflict`/诊断失败降级；属性写入失败时回滚同一次回包中的全部新块。
4. 多块正文更新暂时返回明确的不可用回执。待真实宿主确认 `updateBlock` 的拆块回包、父子关系和失败恢复后，再实现替换式更新；不通过普通失败让用户盲目重试。
5. 该清单是新格式的物理定位元数据，不改变旧数据，不自动合并或删除历史相邻块。真实宿主仍需验证返回 ID 的顺序、同库归属和删除/回读语义。

## 验证要求

受控内核契约覆盖多段创建、完整读回、整体删除、属性失败全量回滚和损坏清单拒读；新增门禁必须注入移除 parts 写入、漏删尾块和绕过多块更新的源码负向并恢复正向。解除 B-006 前，必须在符合 B-005 解除条件的真实宿主覆盖单段、多段、列表/标题/任务、代码围栏、变量与结构场景，并验证更新、导出、回滚和旧数据不误合并。
