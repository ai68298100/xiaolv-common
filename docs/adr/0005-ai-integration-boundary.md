# ADR 0005：AI 融入边界 = 宿主模型 + 默认关 + 正文出域双开关 + 原文不可变

日期：2026-10-06 ｜ 状态：已采纳

## 背景

用户要求融入 AI 能力。产品约束（需求七）：不读取/保存模型密钥、不向外部网络上传用户内容、失败诚实。思源内核已提供 `/api/ai/chatGPT`（一次性补全，用「设置→人工智能」的用户自有模型）与 `/api/ai/listModels`（预检）。

## 决策

1. **模型来源**：只用宿主思源已配置的 AI（chatGPT/listModels 两个端点进白名单）；插件零密钥。
2. **默认关**：侧车 `ai.enabled=false`、`ai.shareContent=false`；门禁测试锁定「任何输入下默认关」。
3. **两级出域**：
   - 仅元数据（默认）：语义找条目（`?` 前缀）只发送 标题/别名/标签/分类/摘要（SearchMetaEntry 结构上不含来源 ID 与正文）。
   - 正文出域：AI 整理/草稿/变换 需 `shareContent=true` 且单次 ≤8000 字符（超长拒绝出域）。
4. **原文不可变**：变换结果仅存内存预览，用户显式选「插入变换结果/复制/插入原文」；绝不回写来源块。
5. **诚实失败**：上游把错误吞为空串（kernel/model/ai.go L75-78）→ 以 listModels 预检 + 空串双判定；未配置/超时(20s)/空响应/解析失败各自明确文案（aiDisabled/aiNotConfigured/aiEmpty/aiTimeout/aiParseFailed）。
6. **prompt 版本化**（PROMPT_VERSION=1），自包含、不清除内核会话缓存（避免动用户 AI 上下文——已知内核 chatGPT 端点带 cachedContextMsg 全局缓存，为已知限制记录于 capabilities.limitations）。

## 功能面（与 docs/positioning.md §四 对应）

| 功能 | 出域级别 | 入口 |
| --- | --- | --- |
| AI 整理（标题/别名/标签/分类建议） | 正文 | 捕获表单「✦ AI 整理」 |
| AI 草稿（描述→模板） | 正文 | 捕获表单草稿行 |
| AI 变换（润色/缩短/正式化/译英/列表化） | 正文 | 动作菜单 ✦ 分区 → 预览三选 |
| AI 语义找条目 | 仅元数据 | 搜索框 `?` 前缀 |
| AI 标签体检 | 元数据 | 规划（P5 后） |

## 后果

- AI 结果质量受内核会话缓存污染的潜在影响（缓解：自包含 prompt；不满足时在产品内如实报错不静默重试）。
- chatGPT 为同步阻塞端点，20s 客户端超时可能早于模型完成 → 超时文案引导重试。
- 未来若内核提供无副作用的一次性补全端点，应迁移（记入 ROADMAP 复查项）。
