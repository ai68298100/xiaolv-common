# ADR 0012：主页面信息层级与轻量视觉语言

## 状态

已接受（2026-10-10）

## 背景

主页面原本把快捷键、搜索规则和保存语义压缩成短符号或内部术语。筛选、排序、空库和空预览状态虽然有实现，但用户需要猜测每一项的含义。设置、首跑和捕获表单也需要与主页面形成一致的卡片层级。R174 复核还发现原型把“收藏/置顶”、库总量/命中数量以及移动端插入能力混在一起，容易让原型与生产状态错位。

## 决策

1. 快捷键采用“键帽 + 动作”两层结构：`↑ ↓ 选择`、`Enter 插入`、`Ctrl/⌘ + Enter 复制`、`Alt/⌥ + 1-9 快速插入`、`Esc 关闭`。Windows 使用 `Ctrl` 文案，Apple 使用 `⌘/⌥`。
2. 搜索框占位符只描述可搜索字段；`?` 语义搜索规则放在搜索框下的辅助提示中，避免把普通搜索和 AI 能力混写成一个隐晦规则。
3. 筛选默认项采用“类型：全部 / 标签：全部 / 分类：全部”，排序入口采用“排序：当前方式”，并给排序菜单项补充规则说明。
4. 空态直接给出下一步和保存位置；空预览说明用户先选择左侧条目。底栏显示“库内条目：N 条”，语义查询显示“AI 推荐：N 条”，错误态不显示伪造的 0 条；保存声明使用“保存到思源文档；来源移动或删除时会提示”。
5. 收藏只作为范围筛选和默认排序的优先显示规则；默认排序下可显示“收藏”首组，其他排序不单独置顶。分类分组、空态和计数都必须与实际查询范围保持一致。
6. 移动端沿用搜索、点按、长按和双按钮结构；直接插入尚未通过真实思源设备验收时，产品和原型都明确显示待验证并以复制为降级路径。
7. 视觉升级只使用现有 CSS、b3 变量、边框、留白和低透明阴影；不依赖渐变建立主要层级，不引入 UI 框架、图表或高频动画，保留现有轻量 DOM、键盘链路和窄屏降级。

## 结果

- 主页面、空态、设置、首跑、捕获和导入页面共享同一组间距、圆角、卡片和状态层级；原型屏 1 与生产计数、排序分组、移动端文案保持同一口径。
- 中英文键集合保持一致，生产 UI smoke 与交互审计锁定关键文案和动作。
- 真实思源 Electron 与 Android 仍按 B-001/B-002 待现场验收，截图和 Chromium smoke 不替代宿主验收。
