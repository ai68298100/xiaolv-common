# ADR 0038：拼音检索汉字字符级定位高亮契约

## 状态

已采纳（2026-10-14，T-0065 / R212）。

## 背景

自 R5 阶段引入 tiny-pinyin 适配层以来，小驴常用支持使用拼音首字母（如 `cy`）或全拼（如 `changyong`）检索中文条目。
但在 UI 渲染层，列表标题高亮算法（`appendHighlighted`）仅执行字面子串匹配。当用户使用拼音搜索时，原标题为中文字符，查询词为拉丁字母，导致命中条目的标题中没有任何字符被 `<mark class="xlc-hit">` 高亮。用户虽然检索到了结果，但无法直观辨识具体是哪几个汉字被命中。

## 决策

1. **拼音汉字字符级定位（Character-level Pinyin Highlighting）**：
   - 纯函数 `findPinyinMatches(text: string, token: string): Array<[number, number]>` 计算汉字字符区间；
   - 仅对纯 ASCII 字母构成的 token 触发拼音定位；中文或特殊符号 token 直接走既有字面子串匹配；
   - **首字母映射**：记录每个字符的首字母及其在原文本中的真实下标，支持在首字母串中滑动查找并还原汉字物理区间 `[start, end)`；
   - **全拼音节映射**：记录每个汉字的全拼音节，支持连续全拼音节滑动匹配并还原对应的汉字物理区间；
2. **区间融合与安全渲染**：
   - 将直接字面命中区间与拼音推导区间汇合，复用 Merge Intervals 算法合并重叠和相邻片段；
   - 严格使用 `document.createTextNode` 与 `mark.textContent` 渲染，绝不使用 `innerHTML`；
3. **优雅降级**：
   - 当 tiny-pinyin 未启用或宿主环境无 ICU 支持时，返回空区间并安全回退到纯字面高亮，保证零异常、零卡顿。

## 验证与边界

- 单元测试覆盖首字母单字/多字连续命中、全拼连续汉字命中、大小写兼容与超长文本保护；
- 负向门禁测试验证算法准确性；
- 生产 UI 冒烟测试断言拼音检索下的列表高亮表现。
