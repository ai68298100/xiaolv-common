# ADR 0010：首跑推荐路径与 UI 状态反馈

日期：2026-10-09 ｜ 状态：已采纳

## 背景

整体 UI 对照原型复核发现，首跑文案建议新建库文档，但模式默认值仍是选择现有文档，且同屏展示现有文档、笔记本和创建控件。按钮的可用条件、笔记本读取状态、空筛选恢复入口与桌面/移动使用说明也需要保持一致。

## 决策

1. 首跑默认选择「新建专用库文档（推荐）」。它只显示笔记本目标、文档标题和确认创建动作；现有文档、文档树、按笔记本作为互斥模式显示各自控件。更改库时回填原有模式与目标。
2. 推荐创建一个库文档，不自动创建笔记本或每类模板文档。模板需在设置中明确导入到当前库文档，分类写在条目属性中。分类到多文档的路由、迁移和部分创建失败恢复均未设计。
3. 笔记本模式索引根目录一级文档，将新增条目写入其中第一个文档；根目录无文档时阻止完成。笔记本列表和根目录检查的加载、空、错误、重试状态显示在设置内。
4. 全部范围的筛选结果为空时说明筛选原因，并提供「清除筛选」与「新建条目」。收藏/最近为空态继续保留各自语义。
5. 移动端使用说明展示点按/长按操作和宿主未验证提示；桌面快捷键只在桌面说明中出现。
6. 笔记本根文档检查、异步按钮和设置分类名称必须在成功/失败后同步状态，不能留下过期的 ready 文案或启用按钮。
7. 文档搜索需显示加载状态；失败时保留接口错误原因并提供重试。搜索空态动作的前缀也必须遵循当前界面语言，不能与本地化按钮文字拼接硬编码中文。

## 理由与边界

当前服务可以枚举已有笔记本并在其中创建文档，但没有创建笔记本链路。将常用语按类别拆成文档会误导用户，因为条目创建和模板导入都写入当前库文档。先明确一个库文档作为真源，能让新增内容、类别与导入路径保持一致。

本轮 smoke 与 Chromium 生产 DOM/CSS 截图验证交互状态和布局。全表面扫描会顺序点击多个设置入口；如果不关闭先前弹窗，弹窗层数统计会把多个独立流程叠加，因此该计数不能单独作为正常用户流程泄漏证据。思源 Electron 与 Android 实机行为仍未验证，继续按 B-001/B-002 标注。
