# T-0114 / R261：Compact Bundle 紧凑分享与直接导入支持

日期：2026-10-19

## 目标

对标 TextExpander 模板分享（S5），为模板包与条目提供轻量级 URL / 紧凑 Base64 字符串分享格式，并让导入管道直接兼容该格式：
1. 解决用户跨团队或在聊天工具（微信/钉钉/飞书/QQ/GitHub issue）中分享常用语或模板包时，必须生成 `.json` 文件并保存上传的不便；
2. 导出 `COMPACT_BUNDLE_PREFIX`（`"xlc-bundle:"`）标准紧凑字符串前缀；
3. 实现 `serializeCompactBundle(bundle: ExportBundle): string`：跨平台安全 UTF-8 Base64 编码，生成易于复制粘贴的单行文本；
4. 实现 `deserializeCompactBundle(text: string): ExportBundle | null`：支持直接粘贴 `xlc-bundle:...` 紧凑文本或 `xlc://import?bundle=...` 伪协议链接；
5. 升级 `validateImport` 校验器：当输入为紧凑分享格式或 URL 链接时自动反序列化为 JSON 文本后校验，保持与标准 JSON 导入完全一致的冲突策略、条目校验与错误边界。

## 实现

- `src/model/transfer.ts`：
  - 基于 Web 标准 `TextEncoder`、`TextDecoder`、`btoa` 与 `atob` 实现了跨平台无依赖的 `utf8ToBase64` 与 `base64ToUtf8`；
  - 导出 `COMPACT_BUNDLE_PREFIX`、`serializeCompactBundle` 与 `deserializeCompactBundle`；
  - `validateImport` 识别 `xlc-bundle:` 与 `xlc://import?` 前缀，执行容错解码后再进入 `JSON.parse`，若格式损坏返回 `reason: "compact-parse"`。
- `tests/transfer.test.cjs`：
  - 新增 `Compact Bundle：serialize/deserialize 往返保真、URL 协议支持与非法数据容错` 专项测试用例，覆盖序列化前缀、反序列化字段保真、`xlc://` 协议格式解析、`validateImport` 双模式支持以及非法 Base64 安全拒绝。

## 状态与边界

Compact Bundle 是对现有文件导入导出的轻量无缝扩展，底层数据结构与版本语义（`schemaVersion: 1`）保持严格一致；超限（超过 `LIMITS.maxImportBytes`）检查继续在解包前生效以防内存膨胀。
