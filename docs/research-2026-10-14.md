## 对小驴常用的借鉴

### 可以直接纳入现有方向

1. **快速收录**：继续强化“选区/当前块/整篇文档/剪贴板/按需发现”入口；补充拖入编辑器或将选中内容拖入面板的可行性评估。当前数据真源是思源块，拖拽只应生成捕获草稿，确认后才写库。
2. **分组与定位**：保留分类分组、收藏/最近/常用排序；增加数字快捷键、Tab 在搜索/列表/预览间切换的设计候选，但必须先做键位冲突和无障碍检查。
3. **内容格式说明**：在使用帮助中明确文本、Markdown、代码、链接、图片/附件、块引用和结构块的插入/复制差异；注释应作为条目元数据或说明字段，不混入正文。
4. **模板变量**：继续扩展地址、邮箱、联系方式、客服回复等模板，并让变量填写、日期、随机选项和片段嵌套沿用同一套预览与取消语义。
5. **检索反馈**：关键词高亮、多关键词组合、空结果引导和可重试错误已具备；后续可增加“最近使用/常用”排序的快捷切换提示。
6. **场景关联的安全替代**：不监听前台应用，也不做自动发送；可以按当前思源文档、标签或目标编辑器上下文提供手动筛选，保持“用户呼出面板后确认”的边界。

### 暂不照搬

- Quicker 的跨应用自动发送、窗口吸附/贴边隐藏、全局输入拦截和云端同步会突破思源块真源、隐私和宿主能力边界。
- 易歪歪的一键发送、前台窗口场景切换和跨应用热键依赖桌面级输入控制；小驴常用目前应继续提供插入、复制、打开来源三种可验证动作。
- 云同步、剪贴板历史和自动替换仍属于路线图明确暂缓项。

### 调研结论

同类产品没有统一采用“每条短语一个文档”。更常见的 GUI 模式是原子 snippet 条目加搜索、标签、收藏或主题组；文件/目录拆分较多出现在配置文件优先的工具，或用来表达较稳定的场景边界。PhraseExpress 明确提供“原文只存一份、链接条目出现在多个集合”的产品先例；Obsidian 模板则是文件夹中的 Markdown 文本，不能作为双链复用的证据。

对小驴常用，建议把“内容”和“常用入口”分开：保留思源原块为唯一正文；标签/类别承担跨场景筛选；用户可以从已选文档、文档树或笔记本中按指定标签批量发现原块。需要收藏成稳定列表的条目，再在专用常用库中登记只含目标块 ID 和用户维护元数据的轻量引用条目。这样专用库仍是可搜索的目录，原文不搬家、不复制；源块更新后调用时读取原文，来源失效时保留显式状态。

### 小驴常用的候选实现分层

1. **零收录成本的标签视图**：沿用现有按需发现和范围选择，增加按指定标签筛选候选块的路径；不写入源内容，用户打开时可即时发现大批量条目。优先限定在用户选择的文档/文档树/笔记本，遵循现有扫描预算，不做无边界全库扫描。
2. **稳定的引用入口**：对勾选条目提供批量“加入常用”操作，在专用库写入引用记录（目标块 ID、标题/别名、标签、类别），不把整段正文复制过去。调用时现场读取目标块内容；另行明确“插入原文、插入块引用、打开来源”的动作语义。
3. **渐进整理而非强制搬迁**：标签视图用于发现，引用入口用于长期精选；收藏/最近继续作为个人快捷层。只有需要分享、导出或独立维护的模板，才考虑正文成为专用库条目。

这是基于公开产品资料和现有仓库架构形成的设计依据，已由 T-0076/R223 落地为“标签视图 + 引用入口 + 可选快照”实现：默认引用入口只保存目标块 marker 和元数据，复制模式仍保留为需要独立副本时的选择；引用条目的摘要、复制和源正文插入会现场读取目标块。隔离内核已验证标签表示与批量读取形状，Electron/Android 宿主行为仍待现场验收。
