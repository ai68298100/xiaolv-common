# 专用库 + 按需发现：完整方案

日期：2026-10-11  
状态：已确定方向，分阶段实施  
关联任务：T-0032 / R179  
关联取舍：[ADR 0014](adr/0014-dedicated-library-on-demand-discovery.md)

## 1. 目标与核心取舍

小驴常用同时解决两件事：

1. 对已经整理好的内容，提供稳定、快速、可分类、可收藏、可插入的调用库。
2. 让用户能够利用已有思源笔记，不必为了使用插件重新录入一遍。

两件事使用不同的范围和生命周期：

| 层 | 作用 | 默认范围 | 生命周期 | 是否进入主搜索 |
|---|---|---|---|---|
| 专用内容库 | 保存、整理、搜索、收藏、插入和复制 | 已配置的库文档/文档树/库模式 | 持久存在于思源块 | 是 |
| 发现会话 | 从已有笔记中找出可能适合收录的内容 | 用户主动选择的页面、笔记本或文档范围 | 当前会话临时存在 | 否 |

专用库是默认工作集和唯一写入目标。发现结果不是第二个搜索库，也不是后台全文索引；用户确认后，内容才复制成新的库条目。

## 2. 为什么不直接把全部笔记本作为库

当前“按笔记本”模式的真实语义是：读取笔记本根目录的文档，并从其中寻找带 `custom-xlc-id` 的条目块；它不是全笔记本全文搜索。文档树模式也有深度和文档数量上限。普通笔记块没有常用条目标记，不应因为切换一个设置就自动混入日常搜索。

直接全局索引会带来四类问题：

- **噪声**：草稿、会议记录、导航标题和临时段落会与真正常用语混在一起。
- **隐私**：用户可能没有意识到整库内容已经进入调用和 AI 语义找范围。
- **性能**：不使用 SQL 时，需要逐级枚举文档、读取块、读取属性和按需读取正文；打开搜索不应触发全库扫描。
- **语义混淆**：普通笔记是原文，常用库条目是可管理的副本；如果两者混在一起，删除、编辑、收藏和来源失效的含义都会变得不清楚。

因此，“全笔记本”只能是用户主动触发的高级发现范围，不能成为默认库模式。

## 3. 数据与安全边界

### 3.1 专用库边界

- 条目仍然是专用库文档中的真实顶层块。
- 正文和元数据仍走思源块与 `custom-xlc-*` 属性。
- 专用库索引、收藏、最近使用、使用次数和 AI 语义找只处理已收录条目。
- 现有 `doc/tree/notebook` 配置继续保留；设置里的“按笔记本”文案必须明确为“索引所选笔记本中已收录的条目”。

### 3.2 发现会话边界

发现会话只存在内存，建议形状如下：

```ts
type DiscoveryScope =
  | {kind: "current-doc"; docId: string}
  | {kind: "current-notebook"; notebookId: string}
  | {kind: "doc"; docId: string}
  | {kind: "tree"; docId: string; maxDepth?: number}
  | {kind: "notebook"; notebookId: string}
  | {kind: "all-notebooks"};

interface DiscoverySession {
  id: string;
  scope: DiscoveryScope;
  startedAt: number;
  candidates: DiscoveryCandidate[];
  progress: DiscoveryProgress;
  cancelled: boolean;
  errors: string[];
}

interface DiscoveryCandidate {
  key: string;                 // 会话内 key，不能当作库逻辑 ID
  sourceDocId: string;
  sourceBlockId: string;
  sourcePath: string;
  itemType: ItemType;
  title: string;
  summary: string;
  status: "candidate" | "in-library" | "same-content" | "possible-duplicate" | "skipped";
  reason?: string;
  contentHash?: string;        // 仅当前会话内存，不能写入侧车
}
```

发现会话必须满足：

- 不写 `loadData`，不保存全文，不把候选放进主索引、收藏、最近使用、使用计数或 provider 区域。
- 不修改原文块、原文属性或原文结构；关闭弹窗、取消扫描或插件卸载后可直接丢弃。
- 只调用思源公开的结构化 API；禁止 SQL、私有 DOM 和隐式后台扫描。
- UI 明确说明“只读取当前思源数据，不上传、不自动修改原文”。AI 不参与默认扫描；若未来提供 AI 标题/标签建议，必须再次确认并遵守现有 AI 双开关。
- 排除已配置专用库文档、回收站和无法确认身份的节点，防止把自己的库再次发现。

### 3.3 收录语义

用户点击“加入常用库”后：

1. 现场读取候选正文并重新校验来源块仍存在，避免扫描期间编辑造成旧内容写入。
2. 在当前专用库写入一个新的块和新的 `xlc-*` 逻辑 ID。
3. 写入 `sourceDocId/sourceBlockId` 回链；块来源类型沿用现有 `block` 语义，不伪造为手动内容。
4. 原笔记不修改，后续原文变化也不会自动同步到副本；来源变化或删除按现有来源失效规则显示。
5. 完成后刷新主索引，并提供“打开原文”和“打开新条目”两个后续动作。

回执必须说清楚：

> 已复制到专用库，原笔记未修改；之后不会自动同步原文。

### 3.4 删除与撤销

删除库内副本永远只删除专用库中的副本，不删除来源笔记。

阶段二提供“撤销本次加入”时，只允许删除本批次新建、且物理块 ID 和逻辑 ID 仍匹配、用户没有继续编辑过的库块。任一条件不满足就跳过并说明原因。撤销失败不能回滚来源，也不能伪造“已撤销”。

## 4. 跨页面动作基线

所有入口最终复用同一套捕获、发现和插入服务，不为不同页面维护平行保存路径。

| 位置 | 快速收录 | 发现已有内容 | 快速调用 | 默认目标 |
|---|---|---|---|---|
| 编辑器选区 | 保存选中内容 | 以选区所在文档作为发现范围 | 打开常用并插入 | 当前光标 |
| 块右键 | 保存当前块 | 从当前文档发现 | 打开常用并插入 | 当前光标 |
| 文档正文右键 | 保存选中内容/当前块 | 从当前文档发现 | 打开常用并插入 | 当前光标 |
| 文档树右键 | 保存整篇文档为条目 | 从此文档发现 | 插入到选中文档 | 选中文档末尾 |
| 顶栏/面包屑/工具栏 | 打开新建或剪贴板捕获 | 从当前文档发现 | 打开常用并插入 | 当前光标 |
| 命令面板 | 保存选区、当前块、剪贴板 | 当前文档/当前笔记本发现 | 插入、复制、打开来源 | 由动作明确指定 |
| 无活动编辑器页面 | 新建或剪贴板捕获 | 选择发现范围 | 复制或打开来源 | 无插入位置 |
| 移动端工具栏/长按 | 保存选中内容或当前块 | 读取当前文档发现 | 点按调用、长按更多动作 | 直接插入待验证，失败降级复制 |

“保存整篇文档为条目”和“从当前文档发现”必须是两个不同动作：前者明确只产生一个整篇 Markdown 条目，后者只展示候选，不会自动写入。

### 4.1 统一动作名称

中文界面统一使用以下动词：

- `保存选中内容`
- `保存当前块`
- `保存整篇文档为条目`
- `从当前文档发现`
- `从此文档发现`
- `加入常用库`
- `插入到当前光标`
- `插入到选中文档`
- `复制到剪贴板`
- `打开原文`

避免使用“导入”“设为库”“插入常用条目到首个选中文档”等容易让用户误解范围或落点的短语。

### 4.2 插入目标冻结与反馈

- 从编辑器打开搜索时记录启动时的编辑器/文档目标，并在搜索弹窗显示“插入到当前光标”。如果目标已经关闭或不可写，插入按钮禁用并说明原因，用户仍可复制。
- 从文档树打开时记录选中文档 ID，显示“插入到：文档路径”；追加失败只报告失败，不回退为写入其他文档。
- 无活动编辑器时主按钮显示“复制到剪贴板”，不伪装成插入。
- 移动端直接插入仍按 B-002 诚实降级为复制；图片位图剪贴板仍按 B-003 说明。
- 所有动作需要加载/执行中禁用，成功、失败、超时、只读和来源失效都给出可定位回执。

## 5. 三阶段实施方案

### 阶段一：跨页面入口与动作语义收口

目标：先让用户在任何页面都知道“如何加”和“加到哪里”，不引入全域扫描。

#### 产品范围

- 将编辑器“常用”入口统一为动作面板，至少包含“插入到当前光标”“保存当前块/选区”“从当前文档发现”。
- 统一顶栏、工具栏、面包屑、编辑器右键、块引用/链接/图片右键、文档树右键和命令面板的动作名称。
- 把现有“捕获当前文档”明确改名为“保存整篇文档为条目”，为未来“从当前文档发现”留出清晰入口。
- 搜索弹窗根据启动入口显示目标横幅；搜索结果、空态、无活动编辑器和移动端降级文案保持一致。
- 空库和首跑三步卡增加三个并列去向：新建第一条、从已有笔记发现、导入模板示例。
- 所有入口统一前置条件：内容库已配置、来源/目标 ID 合法、当前编辑器存在性、目标文档可写性；不满足时按钮禁用或直接打开设置并给原因。

#### 不做的事情

- 不把普通笔记加入主索引。
- 不在后台扫描当前文档或整个笔记本。
- 不把发现候选保存到侧车。
- 不改变“删除条目不删除来源”的安全语义。

#### 验收标准

- 每个入口在未配置、无编辑器、空选区、空剪贴板、只读目标、关闭弹窗和来源失效时都有确定反馈。
- 编辑器入口的实际插入位置与目标横幅一致；文档树入口只能追加到指定文档。
- “保存整篇文档”和“从当前文档发现”在菜单、帮助、命令面板中均能区分。
- 桌面、窄屏和移动端 smoke 覆盖入口可见性、忙态禁用、成功/失败回执；不把 Chromium 或独立内核结果写成 Electron/Android 验收。

### 阶段二：当前文档/当前笔记本发现与批量收录

目标：解决用户“不知道录入什么、已有内容不想重录”的核心问题。

#### 发现范围

- 默认从触发入口的当前文档开始。
- 用户可主动切换为当前笔记本；首次切换显示扫描范围和隐私提示。
- 默认只扫描顶层块；结构块不自动递归，提供“展开此结构”作为明确动作，防止一篇文档变成大量候选。
- 排除专用库文档、回收站、空块、空标题导航、超长块和不支持的宿主块类型，并在结果统计中显示跳过数量和原因。

#### 扫描与候选

- 使用 `getBlockInfo`、`listDocsByPath`、`getChildBlocks`、`batchGetBlockAttrs` 和按需 `getBlockKramdown`，并发上限 4。
- 先读块结构和属性，再按用户选择预览的候选读取正文；打开发现面板不一次性读取所有长正文。
- 候选显示标题、摘要、类型、来源文档路径、块位置、变量/资源提示和当前状态。
- 候选内容只存在发现会话内存；预览缓存有界，关闭弹窗即释放。

#### 去重与收录

- 同一 `sourceBlockId` 已在专用库：标记“已在库中”，默认不勾选。
- 完整规范化 Kramdown 相同：标记“内容相同”，默认不勾选但允许强制加入。
- 标题相同、摘要前缀相同或短文本相同：只标记“可能重复”，不能自动跳过。
- 精确内容判断在加入前重新读取完整正文并计算内存 hash；不把全文或 hash 写入侧车。扫描期间原文发生变化时重新展示候选或要求确认。
- 批量加入逐条执行，返回新增、已存在、内容相同、跳过、失败的明细；部分失败不回滚成功项，失败项可以重试。
- 新条目默认分类为“待整理”，用户可在批量加入前统一修改或逐条覆盖。

#### 交互流程

1. 点击“从当前文档发现”。
2. 显示范围、隐私说明、进度和取消按钮。
3. 结果页支持按状态、类型、来源文档筛选，多选候选。
4. 预览正文并查看“打开原文”。
5. 点击“加入常用库”，确认复制语义和重复策略。
6. 展示逐条回执，提供打开原文、打开新条目、重试失败项和安全撤销本批次。

#### 阶段二验收夹具

- 新块、已在库同源块、不同来源但同正文、同标题不同正文、原文删除、原文移动、扫描期间编辑。
- 单条 API 失败、批量部分失败、取消扫描、重复点击、关闭弹窗后候选释放。
- 验证原文属性和正文未被修改，库副本可搜索、可插入、可打开来源，来源失效可见。

### 阶段三：指定树、指定笔记本与全部笔记本发现

目标：在阶段二稳定后，扩大已有内容的发现半径，同时把性能和隐私风险控制在用户可见范围内。

#### 范围选择

按风险从低到高逐级开放：

1. 指定文档树。
2. 指定笔记本。
3. 全部笔记本（高级选项，二次确认）。

全部笔记本必须明确显示“只读扫描，不会修改原笔记，不会自动加入常用库”，不能在打开插件或打开搜索时自动启动。

#### 独立发现限制

发现限制不直接复用专用库的 2000 条索引上限，单独配置并在 UI 明示：

- 最大笔记本数、文档数、递归深度、块数和候选数。
- 单块最大读取字符数、总扫描时间、并发数（最多 4）。
- 每批 API 调用后让出 UI，支持取消和超时。
- 结果显示已扫描笔记本/文档/块/候选、跳过数、错误数、截断原因和未扫描范围。

超过限制时显示“未扫描完”，不能显示为“没有更多内容”。取消后已发现候选仍可选择，但不自动收录。

#### 性能、隐私与错误

- 只做显式、可取消、分批扫描；不做后台持续全库索引。
- 不向 AI 发送正文；AI 建议另行确认并沿用正文出域开关。
- 某个笔记本或文档失败时保留其他结果，错误可重试；不把部分结果冒充完整结果。
- 大结果集按来源分页/虚拟列表展示，不一次创建数千个 DOM 节点。
- 移动端支持查看和选择候选，但直接插入和资源位图复制继续遵循 B-002/B-003。

#### 阶段三验收夹具

- 多笔记本、多层文档树、数千文档和超限场景。
- 取消、超时、单文档失败、网络瞬断、来源移动/删除、扫描期间内容变化。
- 内存/DOM/主线程长任务观测，确认关闭发现会话后候选正文不残留在侧车。
- Electron 桌面端和 Android 真机分别进行现场验收，自动化 Chromium 和独立内核只能作为补充证据。

## 6. 发布与回退策略

- 阶段一可以作为小版本发布，主要是入口和文案语义收口。
- 阶段二首次引入发现和收录，必须增加单元测试、UI smoke、真实内核写入验收和负向验证；发现失败不影响现有专用库搜索。
- 阶段三必须先完成压力、取消、部分失败和隐私提示验收，再考虑扩大默认可见入口。
- 任一阶段发现扫描不稳定时，可以隐藏发现入口；专用库配置、已有条目和正常插入链路不受影响。
- 不做数据库迁移，不把候选全文搬进侧车；新收录条目沿用现有块属性和导入回执语义。
