# 小驴常用状态审计（2026-10-18）

## 结论

当前发布基线是 GitHub `v0.4.2`；本地 `HEAD=568c615`，工作区干净，尚未发布。插件已经覆盖“捕获 → 元数据 → 搜索 → 预览 → 插入/复制/打开来源 → 导入导出 → provider 协议”的主要闭环。源码、模型、服务与 UI 结构清楚，当前生产检查没有发现类型错误或确定的单块流程回归。

本轮确认的多段缺陷已做一层保守止损：新建条目现在把同一次 `appendBlock` 回包中的全部合法物理块 ID 写入锚块 `custom-xlc-parts`，读取、索引摘要、导出、条件撤销和删除按清单处理；属性失败会回滚同批块。真实宿主的返回顺序、同库归属和回读仍未验证，多块正文更新暂明确返回 conflict；旧条目无清单仍只管理首块，不能猜测历史相邻块。问题继续记录为 B-006/T-0089–T-0090，复杂多段示例（完整简历、公司介绍、结构清单）暂不能标成现场完整可用。

## UI 与原型核对

原型事实源为 `docs/design/prototype.html` 与 `docs/design/design-spec.md`。本轮已同步模板数量为 20、代码示例为字面 `example_posts`、媒体资源限制和 B-006 多块风险。生产 UI 已覆盖搜索双栏、动作菜单、捕获表单、变量卡、设置/首跑、发现、导入策略、移动底部 sheet、空态/错误/来源失效/目标横幅/暗色/窄屏等主要屏幕。

Chrome 离线审计上一轮暴露的搜索 `role=option` 嵌套交互和客服徽标对比度问题已修复：搜索行改为 `list/listitem` + `aria-current`，客服浅色徽标使用 `#166534`，暗色保持高亮色。最新搜索亮色/暗色/移动 axe 矩阵为 0 violations；发现页与其他表面仍以既有专项诊断为准，不能把单一搜索矩阵外推成全插件无障碍全绿。完整历史诊断保存在 `docs/design/audit-2026-10-18/accessibility-diagnostics.json`。

## 代码问题与本轮修复

- 未来版本或读取失败的 state 侧车不再被默认状态写回；设置层明确提示只读保护。
